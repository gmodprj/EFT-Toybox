# 한글화 범위 검토 — F12 밖의 화면들

F12 설정 창은 끝났다(5,136/5,136). 그 밖에 **모드 메뉴·퀘스트·이벤트·장비·대사**가 한국어로 나오는지 재고,
각각 어디를 고쳐야 하는지와 할 만한지를 적는다. 조사 시점 2026-11-06, SPT 4.1.6 / EFT 0.16.9.5.40743, 설치본 `E:\Spt`.

**이 문서는 검토다. 아직 아무것도 고치지 않았다.**

## 결론 먼저

1. **게임 DB 쪽(아이템·퀘스트·목표·상인 대사)이 남은 일의 거의 전부다.** 서버가 실제로 내려주는 한국어 locale 61,125항목 가운데 **영문 산문이 18,798항목, 영문 208만 자**다.
2. 그 18,798 중 **6,441항목은 모드 탓이 아니다** — 바닐라 EFT 의 한국어 자체가 비어 있는 자리다(특히 퀘스트 설명). 모드가 더한 것은 12,357항목이다.
3. **가장 심한 곳은 퀘스트다.** 이름·설명 2,284 + 목표(조건) 4,461 + 대사·메일 1,353 = **8,098항목 / 130만 자**. 퀘스트는 읽어야 할 글이라 영문이면 그대로 막힌다.
4. **아이템 설명은 번역해도 보이지 않는다.** ODT's Item Info 가 모든 아이템의 `Description` 을 자기 정보 블록으로 **갈아끼운다**. 원래 설명은 화면에 안 나온다.
5. 클라이언트 쪽은 작다 — locale 파일을 읽는 플러그인이 **4개**뿐이고, 그중 한글이 있는 것은 ImpactCue 하나다. 나머지 3개와 **ISB 무전 자막 222줄**은 파일만 넣으면 된다(자막은 역컴파일로 확인했다).
6. **다 하는 것은 현실적이지 않다.** 208만 자다. 단계로 쪼개 **퀘스트 → 봇 역할 이름 → 클라이언트 locale 파일 → 아이템 이름** 순으로 하는 것을 권한다.

## 3. 알아 둘 것 — 아이템 설명은 ODT's Item Info 가 갈아끼운다

`5447a9cd… Description`(Colt M4A1)의 실제 값:

```
플리마켓: 153,083₽ | 항목 값: 13,798 | Mechanic'의 평가: 7,727₽ | <color=#FFFFFF>공통</color>

발견 (✔) x1 > The Punisher - Part 5 @ 프라퍼
발견 x2 > Compensation for Damage - Collection @ 펜스
↺ "Gunsmith - Part 15" 메카닉✔ @ 레프 레벨.2 ∈ Colt M4A1 5.56x45 돌격소총
```

원래 설명("Colt M4A1은 5.56x45mm NATO…")은 **남아 있지 않다.** 그래서

- **아이템 설명 960항목을 번역하는 것은 값이 없다** — Item Info 를 끄지 않는 한 화면에 안 나온다.
- 대신 이 블록 안에 **영문 퀘스트 이름이 섞여 나온다**("The Punisher - Part 5"). 상인 이름은 한국어(프라퍼·메카닉)인데 퀘스트 이름만 영문이라 눈에 띈다.

**그리고 이것은 퀘스트를 번역해도 고쳐지지 않는다 (2026-11-06 실측으로 정정).** 처음에 "퀘스트 이름을 번역하면 이 화면도 같이 고쳐진다" 고 적었는데 **틀렸다.** Item Info 는 퀘스트 이름을 **`en` locale 에서 읽는다.**

| 열쇠 `5ae3280386f7742a41359364 name` | 값 |
| --- | --- |
| 서버 `kr` | `건스미스 - 파트 15` ← 바닐라가 이미 한국어로 들고 있다 |
| 서버 `en` | `Gunsmith - Part 15` |
| Item Info 가 `kr` 설명에 써 넣은 글자 | **`Gunsmith - Part 15`** (영문) |

`kr` 에 한국어가 **이미 있는데도** 영문이 찍힌다. 즉 Item Info 의 블록을 한국어로 만들려면 `en` locale 쪽에도 써야 한다 — `SptKoreanLocale` 로 할 수 있지만(사전을 `locale: "en"` 으로 하나 더 두는 꼴) **지금은 하지 않았다.** 영어 사전을 한국어로 덮는 일이라 범위를 따로 정해야 한다.

## 4. 게임 DB locale 을 어떻게 고치나

### 모드 파일을 직접 고치지 않는다

모드 업데이트에 날아간다. [BACKLOG.md](BACKLOG.md) 의 ISB 역할 이름 항목에도 같은 판단이 적혀 있다.

### 서버 모드 하나가 `kr` locale 에 덮어쓴다

F12 쪽을 `SptKoreanConfig` 하나로 처리한 것과 같은 꼴이다 — 사전은 우리 저장소에 두고, 모드는 그것을 읽어 덮어쓰기만 한다.

확인한 제약 둘:

**이 얼개는 만들어 돌려 봤다** — [src/SptKoreanLocale](../src/SptKoreanLocale), 1차 범위는 §7 의 A(봇 역할 이름)다.

| 근거 | 제약 |
| --- | --- |
| **사전에 값을 직접 쓰면 날아간다** (아래) | `LazyLoad.AddTransformer` 로 **변환기를 등록**한다. 사전이 다시 세워질 때마다 입혀진다 |
| 기억해 둔 규칙 — **DB 변경은 아이템 만드는 모드보다 늦게 돌아야 한다** | `PostLoad` 단계여야 한다. 그보다 이르면 모드가 만든 아이템·퀘스트의 키가 아직 없다 |
| `LocaleService.GetLocaleDb(language)` 는 그 언어가 없으면 **조용히 `en` 으로 떨어진다**(역컴파일 실측) | `LocaleService` 를 쓰지 않고 `localeTable.Global` 에 그 언어가 정말 있는지 보고, 없으면 아무것도 하지 않는다 |

### 값을 직접 쓰면 왜 날아가나 — 한 번 틀리고 실측으로 고쳤다

처음 만든 얼개는 `LocaleService.GetLocaleDb("kr")` 로 받은 사전에 그대로 썼다.
`GlobalLocaleDictionary` 에 `[CacheLazyLoad]` 가 붙어 있고 `ImporterUtil` 이 그것을 보고 `cacheValue: true` 로
`LazyLoad` 를 만들므로 `.Value` 가 같은 인스턴스를 돌려준다 — 그래서 남을 것이라고 읽었다.

**모드 로그는 "22항목을 바꿨다" 고 적었지만, 서버에 물어보니 22항목 전부가 영문이었다.**

| 실측 | 값 |
| --- | --- |
| 모드가 `PostLoad` 에서 본 locale 항목 수 | 60,398 |
| 그 뒤 `/client/locale/kr` 이 내려준 항목 수 | **61,125** |
| 우리가 쓴 22항목 | 전부 영문으로 되돌아 있었다 |

빠진 고리는 `LazyLoad.AddTransformer` 가 `Clear()` 를 부른다는 것이다. 우리보다 **늦게** 변환기를 등록하는
모드가 하나라도 있으면 캐시가 버려지고, 다음 읽기에서 **파일을 다시 읽어 등록된 변환기만** 다시 입힌다.
사전에 직접 쓴 값은 그 자리에 없다. 항목이 727개 늘어난 것이 다시 세워졌다는 증거다.

그래서 값을 쓰지 않고 변환기를 등록한다. `LocaleTable.Global` 의 "DO NOT USE THIS PROPERTY DIRECTLY" 주석이
막는 것은 **값을 직접 고치는 것**이고(바로 그 방식이 날아갔다), 변환기를 등록하는 길은 `LazyLoad` 에만 있다.

**교훈: "로그가 바꿨다고 적었다" 는 적용의 증거가 아니다.** 확인은 `node tools/check-locale-dict.mjs` 가
켜져 있는 서버에게 `/client/locale/kr` 을 물어 하는 것이다.

### 5-1. ISB 무전·방송 자막 222줄 — **길이 열려 있다 (역컴파일 실측)**

`BepInEx\plugins\ISBSpecialForcesPlugin\ISBSpecialForces_Audios\Subtitles\locales\` 에 `ch·en·po·pt·ru` 가 있고 한국어가 없다. 각 222줄(ru 만 279줄).

F12 설정 설명은 "Supported: en, pt, ru and ch" 라고만 적어 두었지만, `ISBSOF_Extras.dll` 을 역컴파일해 보니 **허용 목록이 아니다**:

```csharp
private string FindAvailableLocale(string requested) {
    string text = NormalizeLocale(requested);
    if (File.Exists(Path.Combine(_localesFolder, text + ".json"))) return text;
    ...
    return "en";
}
```

`NormalizeLocale` 은 모르는 코드를 **그대로 돌려준다**(`return text`). 게임 locale 코드가 `kr` 이므로 `Subtitles/locales/kr.json` 을 넣으면 `Subtitle Language = Auto` 그대로 집어 간다.
또 `ResolveText` 가 **키마다 영어로 떨어지므로 일부만 번역해도 된다.**

주의: 모드 폴더 안이라 업데이트에 날아간다. 설치 스크립트로 다시 넣는 형태가 맞다.

셋 다 역컴파일로 확인했고 **파일 하나를 넣는 것으로 끝난다.** 셋 모두 `locales/` 를 훑어 **파일 이름을 locale 코드로** 쓰고, 빠진 키는 영어로 채운다.

| 플러그인 | 코드를 어디서 얻나 | 파일 규칙 | 빠진 키 |
| --- | --- | --- | --- |
| Advanced Stash Sorting | `Localization.Culture = LocalizationManager.Culture` | `locales/*.json`, 파일 이름이 코드 | `GetRaw` 가 키마다 `en` 으로 떨어진다 (조용히) |
| Wishlist Extended | `LocalizationManager.ContainsCulture(코드)` 가 참이어야 한다 | `locales/<코드>.json` | `en` 에서 채우고 **키마다 경고를 남긴다** |

뒤의 둘이 경고를 남기므로 **일부만 번역하지 않고 전부 넣었다** — 그러면 로그가 깨끗하고, 경고가 보이면 그것이 곧 빠뜨린 신호가 된다.

### 5-3. 봇 역할 이름 26항목

`ScavRole/*` 가운데 영문 그대로인 것이 26개다(`ScavRole/infectedAssault` = "Infected" 등). [BACKLOG.md](BACKLOG.md) 에 ISB 10개로 이미 올라와 있는 항목이고, 킬 패널·시체 표시·지도 범주에 바로 보인다.
**항목 수가 26개인데 눈에 매우 잘 띈다 — 들인 품 대비 효과가 가장 크다.**

## 6. 재지 않은 것 — 플러그인 DLL 안에 박힌 인게임 UI

F12 창 밖에서 플러그인이 그리는 글자(패널 제목·버튼·HUD 문구)는 **DLL 안의 문자열 상수**라 locale 파일이 없다.
`SptKoreanConfig` 의 `UiStringPatch.cs` 가 이미 그 수를 쓴다 — **Harmony 트랜스파일러로 `ldstr` 을 불러올 때 바꿔치기**하는 방식이고, `ConfigurationManager.dll` 에 대해 33항목이 돌고 있다. 기술은 있다.

**다만 몇 개의 모드, 몇 항목인지 재지 않았다.** 플러그인 245개를 전부 뒤지는 것은 이 검토의 범위를 넘고, DLL 안의 문자열이 화면에 나오는 것인지 로그용인지는 파일만 보고는 못 가린다.
재려면 F12 작업 때와 같은 방법밖에 없다 — **화면을 하나씩 열어 보고 영문이 보이는 것을 적는다.**

**앞으로 이 저장소에서 `tools/stm-call.mjs` 를 Git Bash 로 부를 때는 `MSYS_NO_PATHCONV=1` 을 주거나 앞 슬래시를 떼고 부른다.**

그 선언은 "이 묶음을 다 맡았다" 는 뜻이다. 아직 적는 중에 넣으면 검사 도구가 남은 것을 전부


#### 펴내기가 멱등이 아니었다 — 1차 956개를 지웠다가 되찾았다

2차를 펴내자 **1차 956개가 통째로 사라졌다.** 짝을 **대상 locale(`kr`)** 에 맞춘 것이 원인이었다 —
1차가 이미 적용돼 그 열쇠의 `kr` 값이 한국어였고, 지도의 영문과 짝이 맞지 않아 빠졌다.

기준을 **`en` locale** 로 옮겼다(우리가 건드리지 않으므로 몇 번 펴내도 같은 결과가 나온다). 더불어

- "우리가 바꾼 것" 판정에 **값 대조**를 더했다 — 서버에는 적용돼 있는데 파일에서는 지워진 상태를 되살려야 했다.
- **바닐라가 번역해 둔 열쇠**(기본 파일에서 `en`≠`kr`)는 건드리지 않는다.
- **다른 모드**가 한국어로 바꿔 둔 열쇠도 비켜 둔다.

고친 뒤 1,256개(956 + 300)를 되찾았고 짝이 맞지 않은 문구는 **0** 이다.
**이것도 "로그가 했다고 적었다" 와 같은 함정이었다** — 펴내기는 성공으로 끝났고, 사라진 956개는
경고 줄을 읽어야 보였다.

#### 용어 하나를 바로잡았다

`Operation Aquarius - Part 2` 를 "아쿠아리우스 작전" 으로 적었는데 **바닐라는 "물병자리 작전"** 이다.
같은 영문 이름의 열쇠가 바닐라와 모드에 각각 있어 한쪽만 다르게 적힐 뻔했다. 바닐라 표기로 맞췄다.

퀘스트 이름을 참조하는 목표(`Complete the task X`)에는 **이미 번역한 한국어 이름**을 넣었고,
**업적 이름은 영문으로 두었다** — 업적은 아직 번역하지 않아 한국어로 적으면 화면과 어긋난다.

#### 변환기가 닿지 못하는 열쇠 12개 — 알려진 것으로 남긴다

적용 뒤 검사에서 **값이 다름 12** 이 남는다. 열쇠 12개 가운데 11개는
**`acidphantasm-reffriendlyquests`**, 1개는 **`ExpandedTaskText`** 의 퀘스트 것이고, 그 모드들은 locale 항목을 **마지막 재빌드 뒤에 캐시된 사전에 직접 더한다.** 변환기는
사전이 *세워질 때* 돌므로 그보다 늦게 직접 더해진 열쇠는 지나가지 않는다(변환기가 본 항목 60,398 /
서버가 내려주는 항목 61,125).

`onlyExistingKeys` 를 꺼도 소용없다 — 우리가 쓴 뒤에 그 모드가 덮는다. **숨기지 않고 셈에 남겨
둔다**(서버 오류 48/1/1 을 기준선으로 적는 것과 같은 꼴). 이 수가 12 에서 늘면 새로 생긴 일이다.

```

```

### 설명 1차 묶음 — 머리말은 규칙으로, 본문은 되쓰기부터 (2026-11-06)

설명 묶음(`<24자리 id> description`)을 먼저 **재 보고** 시작했다. 생각과 달랐다.

| 잰 것 | 값 |
| --- | --- |
| 미번역 설명 | 1,603개 / 864,390자 |
| 그 가운데 **머리말** | 71,788자 (8%) |
| **본문** | 792,090자 (92%) |
| 본문을 바닐라 한국어로 되쓸 수 있는 것 | 225개 |
| 손으로 번역해야 하는 본문 | 1,301개 (655,501자) |
| 값이 빈 문자열이라 할 일이 없는 것 | 77개 |

#### 머리말은 ExpandedTaskText 가 붙인 것이고, 고정 어휘가 6꼴뿐이다

```
This quest is (not) required for Collector / Lightkeeper
No keys required.          Requires Key(s):
Leads to:                  Required minimum gun durability: <n>
```

그래서 `tools/gen-quest-descriptions.mjs` 를 새로 만들어 머리말을 규칙으로 옮기고, 목록에 들어가는
**퀘스트 이름·열쇠 이름은 서버가 이미 한국어로 내려주는 값을 되쓴다**(우리 퀘스트 이름 사전 1,243개가
여기서 다시 쓰인다). 본문은 세 길로 얻는다 — ① 바닐라 `kr.json` 의 공식 한국어(ExpandedTaskText 가
영문을 덮어썼을 뿐 원문은 그대로 있다), ② `lang-src/quest-descriptions.json` 의 `byKey` 에 손으로 적은
것, ③ 아직 없는 것은 **건드리지 않는다**(머리말만 한국어로 바꿔 두면 `dump-untranslated` 가 한글을 보고
"다 했다" 로 세어 남은 본문을 놓친다).

1차 묶음은 되쓰기 225 + 손 번역 269 = **494개**를 적었다. 손 번역은 짧은 쪽부터 집었다 — 업적·아레나
조건, 은신처 꾸미기 설명, 사격장 표적 문구, ISB 연작 대사.

#### ExpandedTaskText 는 `TypePriority = int.MaxValue` 로 **일부러 맨 마지막**에 돈다

처음 설치했을 때 **설명 232개가 영문으로 되돌아갔다.** 그 모드도 `AddTransformer` 를 쓰는데, 변환기는
등록 순서대로 적용되므로 **나중에 등록한 쪽이 이긴다.** 우리는 `OnLoadOrder.PostLoad` 였다.

`OnLoadOrder` 는 enum 이 아니라 `int` 상수 묶음이어서 더 큰 값을 줄 수 있다. `PostLoad + 100000` 으로
올리니 오래 걸려 있던 값 다름 12건은 사라졌지만(acidphantasm-reffriendlyquests) 설명 232건은 그대로였다.
DLL 을 뜯어 보니 ExpandedTaskText 는 `int.MaxValue` 를 쓴다 — 더 올릴 자리가 없다.

그래서 **같은 `int.MaxValue`** 로 두었다. 동순위에서는 발견 순서로 갈리는데 `SptKoreanLocale` 이
`ExpandedTaskText` 보다 뒤여서 우리가 나중에 등록된다. 실측 결과 **5241/5241 적용, 값 다름 0** —
남아 있던 12건까지 함께 사라졌다. 다만 이것은 **문서로 보장된 순서가 아니라 동순위 정렬에 기댄 것**이라,
설명이 영문으로 돌아가면 먼저 로드 순서를 본다.

#### 통째로 덮으니 낡을 수 있다 — `sources` 를 적어 둔다

### 설명 2차 — 묶음을 병렬로 나눠 설명을 다 덮었다 (2026-11-06)

1차 뒤 남은 본문 1,031개를 **내가 직접 쓰는 방식으로는 왕복마다 60~70개**가 한계였다. 사용자가 속도를
지적했고, 재 보니 그 말이 맞았다 — 설명은 목표(조건)와 달리 틀이 없어 찍어낼 것이 없다.

#### 265개는 직접, 남은 766개는 번역 에이전트 6개에 나눠 동시에

묶음은 **글 길이로 나눠** 긴 것들이 한 묶음에 모이게 했다(126~128개씩, 5.7만~16만 자). 여섯 묶음 모두

테라피스트·피스키퍼는 존댓말, ISB 지휘관은 단정한 해라체), 무기 제품명은 영문 유지, 줄바꿈 구조 보존,
`Leads to: Nothing` → `이어지는 의뢰: 없음`, 그리고 **내가 앞서 틀렸던 표기 금지 목록**.

보고는 믿지 않고 **받은 파일을 직접 셌다.** 검사 항목: 빠진 id, 깨진 JSON, 한글 없는 값, 영문과 줄 수가
2줄 이상 어긋난 값, 원문의 30% 미만으로 짧은 값(요약 의심). 여섯 묶음 전부 **128/128(6차는 126/126)**

#### 다시 펴내자 1차 묶음 494개가 사전에서 빠졌다

생성기가 "이미 한국어인 값은 건드리지 않는다" 를 **서버의 `kr`** 로 판정했는데, 1차 묶음을 설치한 뒤에는
그 `kr` 이 **우리가 넣은 한국어**다. 그래서 우리 것을 "남이 번역해 둔 것" 으로 보고 걸러냈다. 기준을
**`en`** 으로 바꿨다 — `en` 은 늘 영문이고, 설명 열쇠에서는 ExpandedTaskText 가 덮기 전의 `kr` 과
글자까지 같다(1차에서 494/494 일치 실측). 우리가 맡을 열쇠인지는 `en` 값에 **머리말이 붙어 있는지**로
가른다. 머리말이 없으면 그 모드가 손대지 않은 바닐라 항목이고, 그 `kr` 은 이미 공식 한국어라 우리가
같은 값을 다시 쓸 이유가 없다. 고친 뒤 두 번 돌려 결과가 같은 것을 확인했다.

보도록 고쳤다. 남은 76개는 값이 빈 문자열이라 할 일이 없는 것들이다.
