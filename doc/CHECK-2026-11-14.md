## 5. 설치본 대조 — 검사가 옛 해제본과 견주고 있었다

`check-installed-vs-extracted.mjs` 가 **설정 아닌 차이 1개**를 들고 왔다 — 1453 Make Shotguns

**거짓 경보였다.** 그 모드는 11-09 에 `1.19.1 → 1.20.0` 으로 올렸고, 그래서 해제본이 **두 벌**이다.

| 대조 상대 | md5 |
| --- | --- |
| 설치본 `BepInEx\plugins\makeshotgunsgreatagain.dll` | `080bd533…` |
| `extracted/stage8-F/…`(1.19.1) | `659d9f55…` ← 검사가 고른 것 |
| `extracted/update-2026-11-09-ud/…`(1.20.0) | `080bd533…` ← **설치본과 같다** |

색인이 **먼저 찾은 것을 쓰고 있었다**(`if (!extIndex.has(name))`). 폴더 이름 순서로 `stage8-F` 가
`update-…` 보다 앞서니, 업데이트한 모드는 **언제나 옛 버전과 견주게** 된다.

**고쳤다** — 같은 이름이 여러 단계에 있으면 **가장 새로 해제한 것**(디렉터리 mtime)을 쓴다. 겹친
개수도 첫 줄에 적게 했다. 고친 뒤 다시 돌린 결과는 §7 에 적었다.

> 검사가 녹색이 아닌 것을 들고 왔을 때 **먼저 볼 것은 설치본이 아니라 검사 자신**일 수 있다.
> 설치 기록 쪽에도 같은 종류의 함정이 있다(`install-records-can-misattribute`).
