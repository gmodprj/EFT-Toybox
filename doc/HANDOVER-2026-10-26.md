### 3. WebConfigBridge — 서버 웹 모드 페이지

`src/WebConfigBridge` → `https://127.0.0.1:6969/webconfigbridge`

자체 편집 수단이 없는 서버 모드의 설정을 **탭 10개**로 고친다. `IModBlazorMetadata` + Razor 컴포넌트 방식이며 전례는 `JeroBackpack.ModMetadata`다.

탭: 무기·부품·탄약 호환 / **분류별 칸 열기** / 헬멧 부착 칸 / 지도 표식 / 보험 반환 / 플리마켓 / 수리 버프 / 거래 표시 / 사망 복원 / 무한 치트

주의할 점이 셋 있다.

- 저장은 즉시, **적용은 다음 서버 시작부터**. 대상 모드들이 설정을 시작 때 한 번만 읽는다.
- 저장이 `//` 줄 주석을 지운다. 처음 저장할 때 원본을 `.orig`로 남긴다.
- 모델에 없는 JSON 키는 `TargetConfig`(=`[JsonExtensionData]`)가 보존한다. 설치본의 실제 파일 8개로 왕복 시험을 붙였다(`src/CompatToggle.Tests/ConfigRoundTripTests.cs`, 38개 통과).

모드를 더하는 비용: POCO 하나 + 패널 하나 + `ConfigStore.RelativePaths`에 한 줄.

### 4. SlotCategoryRelax — 분류별로 골라 칸 열기

`src/SlotCategoryRelax`

`AllinWeaponUnslotted`는 칸 확장이 전부 아니면 전무라 "조준경은 열고 핸드가드는 닫는" 구분이 안 된다. 분류마다 켜고 끄는 모드를 만들었다.

- 규칙: 어떤 칸이 켠 분류의 부품을 하나라도 받고 있으면 그 칸에 같은 분류를 모두 넣는다. 넓히기만 하고 좁히지 않는다.
- 고를 수 있는 분류는 고정하지 않는다. 서버 시작 때 DB를 훑어 `discovered-categories.json`으로 내놓고(분류 이름 + 아이템 수), 모드 페이지가 그걸로 스위치를 만든다.
- 분류와 대상 칸 모두 `Mod` 계열로 제한한다. 그러지 않으면 보안 컨테이너·장비 칸까지 훑어 `Ammo`·`KeyMechanical` 같은 분류가 올라온다(57종 → 28종).

**현재 전부 꺼짐**이라 DB를 바꾸지 않는다.

## 남은 일

### A. 탄창 소실 오류 — 해결됨 (2026-10-26 정정)

> **이 항목의 처음 판정은 틀렸다.** 아래가 사실이다.

원인 분석은 맞았다 — `Mag Retention Reload` × `Direct Reload` 충돌이고, 예외 문구까지 2026-10-25의 그것과 같다.

```
[DirectReload] Direct reload failed: Direct load flow error |
System.Exception: Trying to get parent of an item that doesn't have a parent: ★ PMAG D60
```

**틀린 것은 설정 상태였다.** 처음 이 문서는 `BepInEx/config/de.tosox.magretentionreload.cfg` 의 `Enabled`가 **true**로 돌아갔다고 적었는데, 실제 값은 **false**였다. 내가 설정 내용을 15:13:06 쓰기 **이전**에 읽고 파일 수정 시각은 그 **이후**에 따로 읽은 뒤, 둘을 합쳐 "15:13에 켜졌다"고 결론낸 것이다. 그 15:13:06 쓰기가 바로 **끄는** 쓰기였고 그 뒤 파일은 바뀌지 않았다.

그러므로 조치는 이미 되어 있었다. 로그의 예외 2건은 꺼지기 전에 난 것이다.

**검증** — 게임이 15:43에 종료된 뒤에도 그 cfg의 수정 시각은 여전히 15:13:06, 값은 `Enabled = false`다. BepInEx가 종료 시 다시 쓰지 않았다는 것은 메모리 값도 false였다는 뜻이다. 다음 실행은 꺼진 채로 읽는다. 탄창 회수는 UI Fixes가 맡는다(`com.tyfon.uifixes.cfg:420` `Reload Magazines In-Place = true`).

`doc/MODS-GUIDE.md`의 "알려진 충돌"에 **"켜지 말 것"** 경고 상자를 넣었다. 그 항목은 F12에서 다시 켜질 수 있으므로 경고는 여전히 유효하다.

> **교훈** — 파일의 내용과 메타데이터(수정 시각·크기)는 **한 번에 같이 읽는다.** 따로 읽어 합치면 그 사이의 쓰기를 못 보고 거꾸로 결론낸다. 공교롭게도 같은 세션에서 고친 모드 페이지 결함(항목 D)이 바로 같은 모양의 실수다 — 읽은 시점과 쓰는 시점 사이의 변경을 못 본 것.

### D. 모드 페이지의 묵은 값 저장 — 해결됨 (2026-10-26)

패널은 열릴 때 파일을 읽고, 저장할 때 **들고 있던 값을 그대로 썼다.** 페이지를 열어둔 사이 파일이 밖에서 바뀌면(다른 도구·직접 편집) 저장이 그 변경을 되돌렸다. 실제로 겪었다 — `FckWeapons`를 파일에서 false로 바꿨는데 나중에 true로 돌아가 있었다.

읽을 때 파일 내용의 SHA-256 지문을 남기고 쓰기 직전에 다시 읽어 견주도록 고쳤다. 다르면 쓰지 않고 묻는다(덮어쓰기 / 파일 값 불러오기). `ConfigStamp`·`ConfigStore`·`SaveResult` 한곳에서 처리하므로 패널 10개가 같이 고쳐졌다. 경위는 `doc/WORKLOG.md`의 2026-10-26 마지막 항목에 있다.
