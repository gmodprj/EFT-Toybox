## 2. 결함 — 내보낸 파일이 **격자 자리를 잃고 있었다** (§20)

사용자 제보 "리그에 담긴 내용이 우편과 다르다". 재어 보니 `PorterFileItem` 에 `location` 이
**아예 없었다.** 내보낸 파일 넷에서 좌표가 **100% 떨어졌다**(원본에 있던 1,130개 → 0개).
슬롯에 꽂힌 것은 멀쩡하고 **격자에 놓인 것만** 깨졌는데, 1,361개짜리에서는 **916개가 컨테이너
안**이라 그쪽이 다수였다.

- 고친 자리 다섯과 `ItemLocation` 으로 돌리지 않은 이유는 [설계 §21](specs/2026-11-08-profile-porter-design.md).
- 고친 뒤 **974/974 · 62/62 가 글자까지 같다.** 우편 속 자손도 5/5.
- **이미 보낸 우편은 고쳐지지 않는다** — 사용자 결정으로 셋 모두에게 **다시 보냈다**(§22).
  묵은 우편이 같은 글로 나란히 있으므로 **날짜로 가린다**(11-09 08:40 이 맞는 쪽, 묵은 것은
  11-15 에 만료).

개수·`upd`·`slotId` 는 다 맞아서 **기존 관문 어느 것도 잡지 못했다.** 그래서 관문을 둘로 나눴다
— 단위 시험과 [tools/check-porter-location.mjs](../tools/check-porter-location.mjs)(파일에
적힌 것을 프로필과 맞댄다).

## 3. 새 일 — 파일 지우기와 세부 보기 창

설계 [2026-11-09](specs/2026-11-09-porter-file-detail-design.md) · 계획
[2026-11-09](plans/2026-11-09-porter-file-detail-plan.md). Task 7개를 순서대로 구현했다.

- **지우기** — `porter/` 의 그 파일 하나만. 없는 이름·`../`·**잠긴 파일**을 각각 사유로 거절하고,
  **못 읽는 깨진 파일도 목록에 뜬다**(`readable: false`, 지우기만 된다). 씻어서 글자가 바뀌면
  거절한다 — `a:b` 를 지우라면 `a_b.json` 이 지워질 수 있었다.
- **세부 보기** — 왼쪽 나무, 오른쪽은 스태시 격자 / 인게임 장비 판 / 상자 안(격자들 + 슬롯).
  상자 안의 상자로 끝까지 들어가고, **경로 막대**로 돌아 나온다. 읽기 전용이다.
- 전체 브랜치 검토에서 **Critical 1 · Important 8** 이 나와 전부 고쳤다(앱이 죽는 `async void`
  경로, 뿌리에서 끊긴 가지가 안 보이던 것, 상자 격자 칸 수가 0 이면 안에 든 것이 한 톨도 안
  그려지던 것 등). 경위는 설계 §7.

## 4. 가장 값진 것 — **창을 스스로 찍게 만들었다**

이 창은 Start 메뉴에 없는 낱개 exe 라 computer-use 가 접근 요청조차 받지 못한다. 그래서 화면에
**관문이 하나도 없었고**, 사용자가 열어 본 첫 마디가 "다 어긋났는데?" 였다.

```
ProfilePorter.exe --shot <파일이름> <저장경로.png> [상자id]
```

[App.xaml.cs](../src/ProfilePorter.App/App.xaml.cs) 의 개발용 스위치다. 창을 화면 밖에 띄워
레이아웃을 돌리고 `RenderTargetBitmap` 으로 찍는다. 인자가 없으면 평소대로 `MainWindow` 가 뜬다.
**설치본이 아니라 `bin/Release/.../publish/` 의 exe 로 찍으면 사용자가 창을 열어 둔 채로도**
찍을 수 있다(설치는 잠겨서 거부된다).

이걸로 제보를 받을 때마다 찍어 재고 고쳤다 — 격자마다 생기던 420px 빈 판과 제 스크롤바, 세로로만
쌓이던 격자, 세 줄만 보이던 스태시, 그림 없던 장비 칸, 빈 판으로 보이던 작은 파일, 들어가고
나오는 길, 1칸으로 쪼그라들던 총기, 겹침, 조립된 것의 거짓 아이콘. 전부 설계 §9.

### 겹침의 정체 (설계 §9.3)

| 재는 것 | 겹친 칸 |
| --- | --- |
| 원본 좌표 + 디스크 `items.json` 크기 | **0** |
| 돌고 있는 서버가 주는 크기 | **2** |
| 조립 크기(`GetItemSize`)까지 쓰면 | **11** |

**모드가 아이템·부착물 크기를 바꾼 뒤에도 물건은 놓였던 자리에 그대로 있다.** 우리가 잘못 그린
것이 아니다. 큰 쪽이 덮게 두지 않고 **남의 자리 머리 칸 앞에서 멈춘다**(`DetailPlanner.FitSizes`)
— 실측으로 스태시·상자 전부에서 **겹친 칸 0**.

### 아이콘의 한계

아이콘은 tarkov.dev 에서 받는 **그 tpl 의 기본 그림**이다. 그래서 **조립된 것에는 그리지
않는다**(사용자 결정) — 조립 안 된 총을 보여 주는 거짓이 되기 때문이다. **모드 아이템은 그림이
아예 없다.** 인게임 아이콘은 게임이 3D 모델을 그 자리에서 렌더해 만들어 파일로 꺼낼 수 없다.

## 5. 값을 치르고 배운 것

- **md5 가 같아도 최신이 아니다**(앞 세션) 에 더해, **빌드가 소스보다 한 발 늦을 수 있다** —
  알림 코드를 넣고 빌드하지 않은 DLL 을 설치해, 고쳐 놓은 알림이 안 떴다.
- **같은 초에 두 번 내보내면 이름이 겹쳐 거절된다**(`ok: false`). 1초 뒤에 다시 부른다.
- **백그라운드 프로세스는 턴을 못 넘긴다**(§0).
- **화면이 걸린 일은 보는 길부터 낸다**(§4).
