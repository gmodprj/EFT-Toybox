## 값을 치르고 배운 것

**rclone 설정이 사용자 셸에는 없다.** 터미널 탭(사용자의 대화형 PowerShell)에서 돌린
`export-upload.ps1` 이 `Failed to create file system for "gdrive:..." : didn't find section in
config file` 로 죽었다. 그 셸에서 `Test-Path 'C:\Users\deepe\AppData\Roaming\rclone\rclone.conf'`
는 **False** 인데, 에이전트 도구 쪽에서는 같은 경로에 578 B 짜리 설정이 있고 `rclone about` 이
드라이브 용량까지 제대로 읽는다. `--config` 로 경로를 박아도 사용자 셸에서는 여전히 없다.
**업로드는 에이전트 도구 환경에서 돌려야 한다.** 자격증명을 `E:\` 로 복사해 옮기는 길도 있지만,
공개 아닌 토큰을 파일로 더 흘리지 않기로 했다.

**분모가 늘어나면 재시도다.** 42.369 GiB 파일인데 분모가 42.369 → 84.738 → 127.107 로 뛰었다.
`42.369 / 84.738 GiB, 50%` 를 처음엔 "전송은 끝나고 검증 패스가 도는 표기" 로 읽었는데 **틀렸다.**
드라이브를 `rclone lsjson` 으로 보니 그 시점에 파일이 **아직 없었다** — rclone 이 같은 파일을
처음부터 다시 올리고 있었고, 분모는 재시도분이 누적된 것이다. 실제로 **세 번 올렸다.**

| 차수 | 100% 도달 | 결과 |
| --- | --- | --- |
| 1차 | 16:13:55 | 실패 (분모가 84.738 로) |
| 2차 | 16:59:55 | 실패 (분모가 127.107 로) |
| 3차 | 17:32:23 | **`Copied (new)`** |

`--retries 3` 을 줬고 **정확히 세 번째에서 됐다** — 한 번 더 떨어졌으면 거기서 끝났다. 다음에는
더 넉넉히 준다. 회선은 세 차수 모두 20~23 MB/s 로 꾸준했고 **각 차수의 마지막 1분에만** 꺾였다
(809 KiB/s · 1.799 MiB/s) — 끝의 커밋 단계에서 떨어진다는 뜻이다. 42.4 GiB 를 올리려고
127.107 GiB 를 보냈다(실효 6.4 MB/s). **`--log-level INFO` 에는 실패 줄이 한 줄도 남지 않았다** —
rclone 의 low level retry 는 DEBUG 다. 다음에는 `--log-level DEBUG` 나 `--stats-log-level NOTICE`
로 재시도 사유를 남긴다.

**올린 뒤에는 md5 를 대조한다.** rclone 이 스스로 해시를 맞춰 보지만, 그 말만 믿지 않는다.
`rclone lsjson --hash` 의 원격 md5 와 `Get-FileHash -Algorithm MD5` 의 로컬 값을 견뤘다 — 둘 다
같았다(모드 `c8af68c06c7e3bbda5cc27bb87c23310`, 프로필 `cbb05d9c819ae2d4a9656cf48d4e3a87`).
42.4 GiB md5 는 194초였다.

**압축률은 94.3% 다.** 내용이 이미 압축된 `.bundle`·`.dll` 이라 거의 줄지 않는다. 그래서
`CompressionLevel.Fastest` 를 쓴다 — 46 GB 를 13.4분(약 57 MB/s)에 묶었다. 7-Zip 은 이 기계에
없고, 더 세게 눌러도 몇 %를 위해 몇 배를 더 쓰는 거래다.

## 다시 뜨는 방법

```powershell
# 맨 위 $STAMP 를 그날 날짜로 바꾼 뒤 순서대로
tools\export\export-copy.ps1      # E:\Spt -> E:\Spt_Mods_Export\SPT-Mods-<날짜>\
tools\export\export-docs.ps1      # _EXPORT-DOC 문서와 README 생성
tools\export\export-zip.ps1       # zip 둘 (프로필은 JSON 확인 후)
tools\export\export-upload.ps1    # rclone -> gdrive:SPT-Mods/<날짜>/
```

앞의 셋은 **2026-11-10 에 실제로 돌린 것 그대로**다(날짜는 맨 위 `$STAMP` 상수).
`export-upload.ps1` 은 **이번 실측으로 두 군데를 고쳤다** — ① 재시도를 `--retries 10
--low-level-retries 20` 으로 넉넉히 줬다(3 으로는 정확히 마지막 한 번이 남았다), ② 확인을 크기만
보던 것에서 **md5 까지** 견주게 했다. 그래서 이 파일은 **아직 그 상태로 완주한 적이 없다.**

업로드만은 위에 적은 이유로 사용자 셸에서 돌지 않는다 — 에이전트 도구 환경에서 돌리거나,
rclone 설정이 있는 셸에서 돌린다.
