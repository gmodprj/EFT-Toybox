## 5. 수정 — [fixes/2026-11-11-icebreaker-offmap-guard.md](fixes/2026-11-11-icebreaker-offmap-guard.md)

사용자가 **A/B 측정을 건너뛰고 수정부터** 하기로 했다. 설치본 DLL(11.1 MB, 타입 439개)의
메타데이터를 직접 읽어 이름·서명·정적 여부를 확인하고(추측하지 않았다),
[`src/IcebreakerOffMapGuard`](../src/IcebreakerOffMapGuard)(net472, 10,752 B)를 만들어 넣었다.

- `TickVanillaPerfCensus()`(private instance, IL 680 B)는 **Prefix 로 건너뛴다.** 재는 것뿐이고,
  `DevMode`·`DiagHotkeys` 가 둘 다 꺼져 있어도 돌기 때문에 **설정으로는 끌 수 없다.**
- `IcebreakerAcoustics.IcebreakerLoaded()`(static public, IL 64 B)는 **답을 기억한다.** 판정을 다시
  구현하지 않고 캐시가 비면 **원본을 그대로 돌려 결과만** 적으며, 씬 로드·언로드·활성 씬 변경에서
  버린다. 쓰는 가정은 "씬이 안 바뀌면 답도 안 바뀐다" 하나다.
- 아이스브레이커 어셈블리를 **참조하지 않는다**(11 MB 를 끌어오지 않고, 그 모드 없는 설치본에서도
  안 터진다). 이름으로 찾아 null 이면 아무것도 걸지 않고, **한쪽만 못 찾으면 경고**를 남긴다.
  `Update`(IL 6,664 B)에는 손대지 않았다.
- 빌드 경고 0 / 오류 0, 캐시 규칙 시험 **5개 전부 통과**(총 5개).

## 6. 값을 치르고 배운 것

- **목록 전체를 훑는 것과 키워드로 찾는 것은 다르다.** 다운로드 68,200짜리 모드가 키워드에 안
  걸렸다. 분야를 훑을 때는 카테고리까지 받아 와 정규식을 건다.
- **게임·서버는 로그에 생각보다 많이 적는다.** 메모리를 재려고 모드를 찾았는데, 재는 자리는
  이미 로그에 있었다. 다음에 "못 잰다" 고 말하기 전에 로그의 Debug 등급을 본다.
- **생성기가 차수를 모르면 그 차수가 사라진다.** 설치는 됐는데 목록에 없었다 — 생성 결과를
  `grep` 으로 확인하는 습관이 이것을 잡았다.
- **기준선 숫자에는 날짜를 붙인다.** "고유 48" 은 기동마다 달라지는 값이었다.
- **남의 보고는 우리 버전과 맞춰 읽는다.** 1.1.3 보고가 우리 1.1.3 과 같아서 바로 쓸 수 있었고,
  Hideout Cat 보고는 같은 1.1.1 인데도 우리 쪽에서 재현되지 않았다.
- **파이썬은 이 환경에서 조용한 스텁이다.** 문자열 치환을 파이썬으로 하려다 실패했고, Edit 도구로
