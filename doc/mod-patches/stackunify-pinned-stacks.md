# StackUnify — 지금 값으로 구경별 최대 스택을 고정했다

2026-10-28. 구경 **43종**의 최대 스택을 `StackUnify` 설정에 못박았다. 값은 **새로 정한 것이
아니라 지금 쓰이던 값**이다 — 구경마다 "탄약 분류 아이템의 다수 값"을 실측해 넣었다.

## 왜

같은 구경인데 아이템마다 값이 달랐다. `ReportOnly` 로 전수 조사하니 **44종 중 15종이 한 구경
안에서도 갈려 있었다.**

| 구경 | 갈려 있던 모습 |
| --- | --- |
| `Caliber9x18PM` | 150×44, 1×17, 50×2, (없음)×1 |
| `Caliber12g` | 60×46, 20×14 |
| `Caliber26x75` | 60×14, 1×10 |
| `Caliber40x46` | 5×32, 1×4 |

바닐라 탄과 모드 탄이 섞여 있고 모드마다 자기 것만 손대기 때문이다. 이제 한 구경은 한 값이다.

## 어떻게 골랐나

- 구경별 **다수 값**. 수가 같으면 **큰 쪽** — 스택이 줄어드는 쪽을 피한다.
- **탄약 분류(`Ammo`)인 것만** 세어 다수 값을 구했다. 탄약 상자나 로켓이 섞이면 기준이 흐려진다.
- 바뀐 67~77개는 **전부 늘어나는 쪽**이다. 줄어드는 것이 없으니 프로필에 들어 있는 스택이
  무효가 될 일이 없다.

## 확인

서버를 다시 띄워 `POST /client/items` 로 최종 목록을 받아 확인했다.

| | 결과 |
| --- | --- |
| 값이 하나로 모인 구경 | **43 / 43** |
| 아직 섞여 있는 구경 | 0 |
| 정한 값과 다른 구경 | 0 |
| 제외한 6개 | 그대로 (전부 1) |

모드 로그: `바꿈 77개, 이미 같음 888개, 건너뜀 6개` / `그중 76개는 다른 모드가 이미 다른 값을
넣어 둔 자리였다`.

> 사전 집계로는 67개가 바뀔 것으로 봤는데 모드는 77개를 바꿨다. 차이는 **값이 아예 없던 항목**
> (사전 집계에서 뺐다)과 조사 시점 이후에 다른 모드가 쓴 것이다. 최종 상태는 위 표로 확인했다.

## 되돌리기

설정 파일 하나만 지우면 된다.

```
E:\Spt\SPT_Runtime\user\mods\StackUnify\config.jsonc
```

저장소의 기본 설정([../../src/StackUnify/config.jsonc](../../src/StackUnify/config.jsonc))은
**비어 있다** — 그것으로 덮으면 이 모드는 아무 일도 하지 않고, 값은 다시 모드들이 정하는 대로
돌아간다. 서버를 다시 켜야 적용된다.

## 주의

- 이 설정은 **저장소에 기본값으로 넣지 않았다.** 다른 설치본에서는 다수 값이 다를 수 있어,
  값을 베껴 쓰는 것보다 `ReportOnly` 로 다시 재는 쪽이 맞다.
- 탄약 모드를 새로 넣으면 그 모드의 탄은 이 목록에 없어 **구경 규칙에 따라 같이 고정된다.**
  그걸 원하지 않으면 `ExcludedItemIds` 에 넣는다.
- 화폐는 못 고정한다. BarterItemsStacks 가 이 모드보다 뒤에 쓴다 —
  [../../src/StackUnify/README.md](../../src/StackUnify/README.md) 의 "못 이기는 것".
