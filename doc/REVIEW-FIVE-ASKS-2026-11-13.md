순서도 그대로다 — 기동 로그에서 `UltimateFlea … Pool applied (mode=blacklist): +0 enabled, -0 removed`
→ `[The Blacklist] Found 916 blacklisted …` → `RagfairServer 플리마켓 상품 생성 중`.
**TheBlacklist 가 뒤에 돌고, UltimateFlea 의 풀이 `+0/-0` 이라 실제로 부딪히는 자리는 없다** —
11-12 가 적은 "조건부 무충돌" 이 유지된다. UltimateFlea 쪽 풀을 켜면 이 결론은 깨진다.

### 가격표 넷은 **어떻게 확인하나** (2026-11-13)

물음을 먼저 바로잡아야 한다. **표끼리 값이 다른 것은 당연하다** — 핸드북 가격과 플리 시세는
원래 다른 숫자다. 볼 거리는 "**같은 뜻의 숫자를 두 모드가 서로 다르게 말하느냐**" 이고,
그것은 세 단계로 좁힌다.

**1단계 — 파일로 읽히는 표부터 견준다(인게임 필요 없다).** 넷 중 디스크에 표를 두는 것은
`UltimateFlea` 뿐이다(`data/economy_state.json`, 8,737항목). `QuickSell`·`ShowMeTheMoney` 는
**런타임에 만든다**(QuickSell 은 라이브 플리 9.3만 호가에서 9,765개를 뽑는다) — 파일에 없다.
`TheBlacklist` 는 표가 아니라 **배수 규칙**이다(`Config/*.jsonc`).

오늘 그 1단계를 돌렸다. UltimateFlea 의 `basePrice` 는 **지어낸 값이 아니라 바닐라에서 끌어온 것**이다:

| UltimateFlea basePrice 의 출처 | 항목 | 규칙대로인 것 |
| --- | --- | --- |
| 바닐라 플리 평균가(`templates/prices.json`)가 있는 것 | 2,580 | **2,450** 이 그 값과 **같다** |
| 없어서 핸드북만 있는 것 | 1,465 | **1,451** 이 **핸드북 × 0.75** 다 |
| 둘 다 아닌 것 | 144 | — |

그래서 "핸드북과 4,042개가 다르다" 는 **어긋남이 아니라 설계대로**다(핸드북가 ≠ 플리가).
견줄 때는 반드시 **같은 뜻의 숫자끼리** 놓는다.

**2단계 — 화면에서 볼 아이템을 몇 개로 줄인다.** 위 표의 **144개**(규칙에서 벗어난 것)와,
TheBlacklist 가 배수를 거는 품목에서 5~10종만 고른다. 전수로 볼 일이 아니다.

**3단계 — 그 몇 개를 들고 인게임에서 네 자리를 본다.** 같은 아이템 하나에 대해
① 플리마켓 매물 호가 ② 인벤토리 가격 표시(ShowMeTheMoney) ③ 빠른 판매 금액(QuickSell)
④ 상인 판매가 를 적는다. **①과 ③이 다르면 진짜 어긋남**이다 — 둘 다 "지금 플리에서 받는 값" 을
말하기 때문이다. ②·④는 뜻이 달라 달라도 정상이다.

**2단계도 했다 (2026-11-13).** 규칙에서 벗어난 **144개**를 갈라 보니 **128개가 탄약 박스·팩**이었다

빈 상자 템플릿 값이라 30~90배씩 벌어진다. **어긋남이 아니라 뜻이 다른 숫자**이므로 화면에서 볼 거리가 아니다.

## 4. 플리마켓의 레벨별 구매·판매 제한 — **지금은 꺼져 있다**

11-12 감사는 "`UltimateFlea` 가 이미 2,148개를 잠그고 있다. 새로 만들 것이 없다" 로 닫았다.
**그 문장은 지금 사실이 아니다.**

```
E:\Spt\SPT_Runtime\user\mods\UltimateFlea\config\levels.json   (파일 시각 11-12 20:21)
  "enabled":     false
  "lockBuying":  false
  "lockSelling": false
```

로그가 이것을 뒷받침한다 — `Level locks applied: 2148 items, 15 handbook categories locked` 줄은
**11-12 20:07 KST 기동이 마지막**이고, 그 뒤 기동 **여섯 번(UTC 11:31 · 12:09 · 12:19 · 12:25 · 12:32 · 22:52)에는
한 줄도 없다.** 파일 시각 20:21 KST(= 11:21 UTC)가 마지막으로 걸린 기동과 처음 안 걸린 기동 **사이**에 있다.
오늘 기동의 UltimateFlea 줄은 `Trade hooks enabled` · `Pool applied` · `Economy initialized` · `Loaded` 넷뿐이다.

- **표는 그대로 남아 있다** — `items` 에 아이템 **44개**(레벨 25~50), `categories` 에 핸드북 분류 **22개**(레벨 5~50).
  2,148 이라는 수는 이 분류 22개가 펼쳐진 결과다.
- 그러니 **"특정 아이템을 특정 레벨부터" 를 하려면 새로 만들 것은 여전히 없다.** 세 손잡이를 `true` 로
  돌리고 표를 손보면 된다. 설정은 서버 웹 UI(`/ultimateflea/app.html`)에서도 열린다.
- **왜 꺼졌는지는 모른다.** 파일 시각(11-12 20:21)이 그 직전 기동과 다음 기동 사이에 있어 **그때 꺼진 것**은
  분명하지만, 우리 작업 기록에는 이 파일을 건드린 줄이 없다.
- **사용자가 끈 채로 두기로 정했다 (2026-11-13).** 그러니 `levels.json` 의 세 손잡이는 **건드리지 않는다** —
  다음 사람이 "꺼져 있으니 켜야 하는 것" 으로 읽지 않도록 여기 적어 둔다. 레벨 잠금이 없는 것이
  지금의 **의도된 상태**다. 표(아이템 44개·분류 22개)는 그대로 두므로, 나중에 켜고 싶으면
  `enabled`·`lockBuying`·`lockSelling` 을 `true` 로 돌리기만 하면 그 자리에서 다시 2,148개가 잠긴다.
- 템플릿 자체에는 레벨 자리가 **없다**(11-12 확인). `ISB-Aishi` 만 자기 상인·아이템용 `minPlayerLevel` 류를 든다.

3. **검색 힌트가 오른쪽에서 잘린다** — `400개 — 더 있다. 좁혀 본다` 가 `…좁혀 본` 에서 끊긴다.
4. **프리셋 단추 넷이 두 줄로 접힌다**(`새로`·`복사`·`삭제` / `입은 것`). 2026-11-07 에 일부러 `WrapPanel`
   로 둔 자리라 **고장은 아니지만**, 칸 너비를 기억하게 하면 한 줄로 설 수 있다.

### 5-3. ProfilePorter 는 **메인 창에 화면 관문이 없다**

`--shot` 은 두 도구에 다 있지만 **범위가 다르다.**

| | 찍히는 것 |
| --- | --- |
| `AirdropCaller.exe --shot <png> [초]` | **메인 창** |
| `ProfilePorter.exe --shot <파일이름> <png> [상자id]` | **세부 보기 자식창만** (`FileDetailWindow`) |

2026-11-09 에 사용자가 "다 어긋났는데?" 라고 제보한 그 창이 **메인 창**이었고, 그때 `--shot` 은
자식창을 고치려고 만들어졌다. 지금도 메인 창(프로필 목록·스태시 격자·파일 목록·받는 쪽)은
**사람이 열어 봐야만** 확인된다. 오늘 메인 창을 찍으려 했으나 인자 형식이 달라 창이 그냥 떠서 멈췄다.

### 5-4. 아직 확인되지 않은 채 남아 있는 것 (설계 문서에서 옮김)

- **AirdropCaller**: 인게임에서 `조립만 보기` 를 눌러 본 적이 없다. 라우트와 단추는 껐다 켠 서버로
  네 번 확인했지만(설계 §23), 레이드 중에 눌렀을 때 그 레이드에 아무 일도 없는지는 보지 않았다.
- **ProfilePorter**: 세부 보기 창의 장비 판 배치·격자 크기는 `--shot` 으로 닫혔지만,
  **메인 창**은 위 §5-3 대로 관문이 없다.
