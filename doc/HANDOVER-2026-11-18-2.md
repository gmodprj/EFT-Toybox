## 2. ProfilePorter 세 가지 (PR #130)

| 물음 | 답 |
| --- | --- |
| 한 번에 2048개 상한의 근거 | §9.1 실측의 최대(Nomad 1,358개)를 보고 둔 여유값이었다. SPT 쪽 제한이 아니다 |
| 툴팁 글자가 안 보인다 | 앱 전체에 건 `TextBlock` 기본 스타일(밝은 글씨)이 툴팁 안에도 걸리는데, 툴팁 바탕은 WPF 기본 흰색이었다. `App.xaml` 에 어두운 `ToolTip` 스타일을 더했다 |
| 창 크기·칸 간격이 다시 켜면 돌아간다 | 남기는 코드가 없었다. `WindowLayout.cs`(새로) 가 exe 옆 `profile-porter.layout.json` 에 위치·크기·최대화·별 칸 너비를 닫을 때 적고, 열 때 되살린다. 메인 창(`main`)과 파일 상세 창(`detail`) 둘 다 |

- 배치 파일은 설정 파일(`profile-porter.config.json`)과 **따로** 둔다. 지워도 된다 — 기본 배치로 연다.
- 툴팁은 computer-use 로 앱 창을 볼 권한을 받지 못해서(사용자 거절), XAML 을 화면 밖에서 그려 색을 셌다: 고치기 전 흰 상자, 고친 뒤 글자가 나온다. **실제 앱 화면으로 본 것은 아니다.**
- `--shot` 길(앱이 스스로 찍는 경로)에는 배치를 걸지 않았다 — 찍는 크기가 매번 같아야 한다.

## 3. 상한 2048 → 4096 (PR #131, #132)

- SPT `MailSendService.SendSystemMessageToPlayer` 를 디컴파일해 보니 **개수 제한이 없다.**
- Nomad 스태시 2,067개를 실제로 내보내 Talon 에게 들였다(들이기 전 백업 `backups/20261118-015940`).
  디스크에서 2,067개·`main` 뿌리 97개·고아 0·중복 id 0 을 확인했고, **사용자가 게임에서 받았다**("정상 들어감").
- `ExportSelection.MaxItems` 하나를 `ImportPlanner` 도 함께 쓴다. 넘으면 "나눠서 하세요" 로 거절한다.
- **4096 은 잰 양(2,067)의 두 배쯤이다. 그보다 큰 한 통은 재지 않았다.**
