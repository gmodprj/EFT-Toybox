## 3. 절차

0. **게임·서버를 다시 켠다.** 오늘 클라이언트를 여러 번 바꿨다(최신 `7A605C1A`). 서버는 그대로다.
1. **Banshee 를 초대한다.** 파티에 들어온 것을 확인한다.
2. **"실물로 나간다" 를 로그로 확인한다** — 출격 직후 서버 로그에:
   `[STM] 'Banshee'(aid 1741641) 를 Real 장비로 내보낸다: …`
   **`Temporary` 라고 찍히면 중단한다.** 임시 장비는 애초에 지울 것이 없어(정책 3번 규칙) 이 관문이
   아무것도 증명하지 못한다.
3. **레이드에서 Banshee 를 죽인다.** 가장 확실한 방법은 플레이어가 직접 쏘는 것이다 - "탈출 실패" 는
   **그 팀원 자신의 사망 보고**(PIT 의 `Escaped`)로 정해지지, 플레이어의 생사로 정해지지 않는다.
4. **플레이어는 탈출한다.** 레이드가 끝나야 보고가 가고 그때 이 경로가 돈다.
5. **게임을 끄고**(저장이 끝나게) 아래 확인으로 간다.

## 4. 확인 — 로그 (서버, 시각은 UTC. 탐색기 시각과 9시간 차이다)

성공이면 이 네 줄이 순서대로 있어야 한다:

```
[STM] 레이드 결과 접수: 'Banshee'(aid 1741641, 프로필 '6ae5870e…', 레이드 '…') escaped=False
[STM] 레이드 결과: 'Banshee'(프로필 '…', 레이드 '…') - 실물 장비로 나갔다가 돌아오지 못해 착용 장비를 지운다.
[STM] 레이드 결과: 'Banshee'… 착용 장비 9개(하위 포함 142개)를 지우고 저장했다(…ms) - …
[STM] 레이드 결과 확인: 프로필 '…'에서 아이템 142개가 모두 사라진 것을 메모리에서 다시 확인했다.
```

**숫자가 핵심이다**: `9개(하위 포함 142개)`. 다르면 정책이 고른 것이 내 계산과 다르다는 뜻이므로,
프로필을 고치기 전에 그 차이부터 설명해야 한다.

## 5. 확인 — 프로필 대조

```bash
node tools/stm-profile-diff.mjs backup/2026-11-04-before-death-gate
```

기대: **Banshee 만 변한다.** `아이템 264 → 122`, 사라진 id 142개가 기대값 파일의 `goneAll` 과 **정확히
같고**, 남은 91개 안에 보안 컨테이너·주머니·완장·인식표·스태시 56개가 전부 있다. 다른 여섯 프로필은
"변화 없음", **새로 생긴 id 충돌 0**.

사라진 id 를 기대값과 기계로 맞추려면:

```bash
node -e "const e=require('./backup/2026-11-04-death-gate-expected/banshee-expected.json');const fs=require('fs');const a=JSON.parse(fs.readFileSync('E:/Spt/SPT_Runtime/user/profiles/6ae5870eeb15d61bf003fd1f.json','utf8'));const now=new Set(a.characters.pmc.Inventory.items.map(i=>i._id));const stillHere=e.goneAll.filter(id=>now.has(id));const alsoGone=e.stay.filter(s=>!now.has(s.id));console.log('지워졌어야 하는데 남은 것:',stillHere.length,stillHere.slice(0,10));console.log('남아야 하는데 사라진 것:',alsoGone.length,alsoGone);"
```

**둘 다 0 이어야 통과다.** 두 번째가 0 이 아니면 **즉시 멈추고 백업에서 되돌린다.**

## 6. 실패 신호와 그 뜻

| 로그 | 뜻 | 할 일 |
|---|---|---|
| `보고에 탈출 여부(Escaped)가 없다` | 클라이언트가 생사를 안 보냈다 | 지운 것이 없다. PIT 보고 경로부터 본다 |
| `탈출 여부가 아직 정해지지 않았다(RollEscape)` | PIT 가 탈출을 주사위로 정하는 중 | 지운 것이 없다. 설정을 보고 다시 돈다 |
| `어떤 장비로 나갔는지 기록이 없어` | 스폰과 레이드 종료 사이에 서버가 재기동됐다 | 지운 것이 없다. 다시 돈다 |
| `임시 장비로 나가` | 2번 단계를 건너뛴 것이다 | 관문이 성립하지 않는다. 장비를 채우고 다시 |
| `레이드 식별자가 비어 있다` | 영수증을 쓸 수 없다 | 지운 것이 없다 |
| `손상/적재 불가로 표시돼 있어` | SPT 가 그 프로필을 못 읽는다 | 지운 것도 영수증도 없다. 프로필을 먼저 고친다 |
| `인벤토리를 읽을 수 없어` / `장비 루트…가 비어 있어` | **영수증은 이미 예약됐다** | 이 레이드는 다시 처리되지 않는다. 지우려면 사람이 직접 |
| `레이드 결과 확인 실패: … 그대로 있다` | 지웠다는데 남아 있다 | **가장 나쁜 신호.** 프로필을 직접 보고 백업과 대조 |

## 7. 되돌리는 법

게임과 서버를 끈 뒤:

```bash
cp backup/2026-11-04-before-death-gate/*.json /e/Spt/SPT_Runtime/user/profiles/
```

되돌린 뒤 `node tools/stm-profile-diff.mjs backup/2026-11-04-before-death-gate` 가 전부 "변화 없음" 이면
원래대로다. **영수증은 되돌아가지 않는다** - 같은 레이드 id 로는 다시 처리되지 않으므로, 다시 시험하려면
새 레이드를 돈다.

## 8. 이 관문이 증명하지 못하는 것

- **임시 장비로 죽은 경우**(정책 3번 규칙)는 별도다. 지울 것이 없다는 것을 확인하려면 장비 없는 프로필로
  한 번 더 돌아야 한다.
- **플레이어가 시체에서 털어 온 것의 보호 해제**(`RaidProtectionReleasePolicy`)는 이 관문에서 함께 돈다.
  Banshee 의 시체를 털어 나왔다면, 턴 물건이 플레이어에게 **남아 있는지**까지 봐야 한다(설계상 남는다 -
  지운 것만 넘겨준다).
- **멱등**(같은 레이드 두 번 처리 안 함)은 로그의 영수증 줄로만 보인다. 일부러 두 번 보내려면 라우트를
  직접 불러야 한다.
