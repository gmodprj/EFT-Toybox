# 상인 화면 목록 보기 (TraderListView) — 설계

2026-11-18. 상태: **승인됨**(사용자, 2026-11-18) (빌더 점검 반영 — 격자 정렬 자리 정정, 가격 환산 기준, C 범위, 헤더 배치 결정).

## 1. 왜

AIOTrader 같은 상인은 물건이 수천 개고, 지금 상인 화면은 아이콘 격자 하나뿐이라 찾고 견주기가 어렵다.
사용자가 원한 것은 셋이다(2026-11-18).

1. **EDIT ASSORTS 버튼이 검색창을 가린다** — 고친다.
2. 상인 목록을 **가격·이름·재고로 정렬**한다.
3. 상인 목록을 **플리마켓처럼 줄 단위 목록**으로 바꿔 볼 수 있게, **상인 화면 안에** 새로 그린다.
   "상인 화면에서 플리마켓으로 넘어가 그 상인 것만 보기" 는 사용자가 **명시적으로 거절**했다(싸도 안 된다).

## 2. 목표 · 안 할 것 · 실패로 칠 것

| 목표 | 안 할 것 | 실패로 칠 것 (돌아가도 실패) |
|---|---|---|
| 상인 화면 구매 모드에 **격자 ↔ 목록** 전환 버튼 | 판매 모드(내 창고 쪽) 목록화 | 목록에서 산 것이 **상인 거래가 아닌 다른 경로**로 사지는 것 |
| 목록 열 머리를 눌러 **가격·이름·재고·등급** 정렬, 오름/내림 | 상인 데이터(가격·재고) 수정 | 목록과 오른쪽 구매 창이 **다른 물건**을 가리키는 것 |
| 같은 정렬을 **격자 보기에도** 적용 | 플리마켓 화면 수정 | 검색(Trader Search)·신뢰 등급 탭을 목록이 **무시**하는 것 |
| 겉모습은 플리마켓 목록을 **닮게**(줄 배경·글꼴·색) | 서버 모드 | 수천 줄에서 화면이 **멈추는** 것 |
| EDIT ASSORTS 와 검색창 **겹침 해소** | | 다른 상인 화면 모드(아래 §6)를 깨는 것 |

## 3. 고른 방식 (사용자 결정: B 로 시작해 C 의 겉모습)

| | 방식 | 판단 |
|---|---|---|
| A | 플리마켓 행 부품을 복제해 상인 물건을 플리 매물처럼 넣는다 | 버림 — 행이 플리 매물·플리 구매 흐름에 묶여 있다. "구매" 가 플리로 사려 들고, 게임 갱신에 가장 잘 깨진다 |
| **B** | **목록을 우리가 직접 그리고, 줄을 누르면 원래 구매 창에 맡긴다** | **고름** — 사는 흐름이 지금과 같아 돈·물건 사고의 자리가 없다. 정렬이 같은 목록에서 끝난다 |
| **C** | B 위에 플리 행의 겉모습(바탕 이미지·글꼴·색)만 빌린다 | **B 다음 단계로 고름** — 겉모습만 가져오므로 B 의 안전함을 지킨다 |
| (기각) | 플리마켓으로 넘어가 그 상인만 보기 | 사용자 거절 |

## 4. 게임 쪽 연결점 (실측: `Assembly-CSharp` 디컴파일, SPT 4.1.6 / EFT 0.16.9.5)

| 필요한 것 | 어디서 |
|---|---|
| 상인 화면 | `EFT.UI.TraderDealScreen` — `_traderGridView`(상인 격자), `_traderScroll`, `_updateAssort`(상점 새로고침 버튼), `_allItemsTab`·`_loyaltyTabs`, `TradeMode`, `OnTradingModeChanged` |
| 상인 격자에 놓일 물건 목록 | `TraderDealScreen.PrepareTraderGrid()` 가 신뢰 등급 탭으로 거른 `IReadOnlyCollection<Item>` 을 `TradingGridView.Show(items, …)` 에 넘긴다. 격자는 **고정 칸 위치를 그리지 않는다** — `TradingGridView.ApplyFilter()` 가 매번 새 `ReferenceGrid(10×25, 세로로 늘어남)` 을 만들고 `ItemSorter.Sort(FilterPanel.GetFilteredItems(_items))` 순서대로 `Grid.AddAnywhere` 한다(실측). 그래서 **`PrepareTraderGrid` 반환값을 다시 줄 세워도 여기서 `ItemSorter.Sort` 가 되돌린다.** 정렬은 **상인 쪽 `TradingGridView`(= `TraderDealScreen._traderGridView`) 의 `ApplyFilter` 안 정렬을 우리 비교로 바꿔서** 격자에 먹인다(판매 쪽 `_stashGridView` 는 건드리지 않는다). **목록의 집합도 같은 자리의 `FilterPanel.GetFilteredItems(_items)`** — 여기서 등급 탭·카테고리 필터·Trader Search 검색어가 이미 걸린다 |
| 구매 창과 잇기 | 격자 아이템 클릭 = `TradingItemView.OnClick` → `_traderAssortment.SelectItem(Item)`. 오른쪽 구매 창은 `Assortment.SelectedItemChanged` 를 따른다. **목록 줄 클릭도 `Assortment.SelectItem(item)` 만 부른다.** 선택 표시는 `SelectedItemChanged` 를 구독해 맞춘다 |
| 가격 | `Assortment.GetBarterPrice(item)` → `Trader.ItemPrice?`(`CurrencyId`, `Amount`). 물물교환은 바터 스킴(재료 목록)에서 요약 |
| 재고 | `item.StackObjectsCount`(상인 재고 999999 같은 값 그대로) + 구매 제한이 있으면 남은 수 |
| 신뢰 등급 | `Assortment.LoyalLevelItems[item.Id]`. 지금 등급보다 높으면 잠금 표시 |
| 갱신 | `Assortment.AssortmentUpdated`, `TraderDealScreen.UpdateGridViews` 가 격자를 다시 그릴 때 목록도 다시 만든다 |

## 5. 화면

```
[ 상점 새로고침 ][ 검색창 ............................ ][✎][▦|☰]   ← 헤더 한 줄
 정렬: 기본 · 가격▲ · 이름 · 재고 · 등급                           ← 격자 보기에서만 보이는 작은 정렬 막대
┌──────────────────────────────────────────────────────────────┐
│ [아이콘] 이름 ▲            │ 가격 ▲           │ 재고     │ 등급 │  ← 목록 보기: 열 머리 클릭 = 정렬
│ [■] FN SCAR-L Black Market │ 1 ₽              │ 999999   │ LL1  │
│ [■] KA-BAR USMC 나이프     │ ⇄ 물물교환 2종   │ 50 (3/일)│ LL2🔒│
└──────────────────────────────────────────────────────────────┘
```

- **헤더 겹침(1번)**: EDIT ASSORTS 를 **연필 아이콘만 남긴 좁은 버튼**(검색창 높이의 정사각형)으로 줄이고 검색창 오른쪽에 둔다. 검색창은 남은 폭을 쓴다. 그 오른쪽에 격자/목록 전환 버튼. 두 모드가 자기 자리를 잡은 **뒤**(각자의 Show 패치보다 늦게) 우리가 다시 배치한다. **사용자 결정(2026-11-18): 연필 아이콘만 남긴다**(헤더를 두 줄로 내는 안은 버렸다). Assort Editor 버튼은 이름 `UTAE Edit Assorts Button` 으로 붙고(디컴파일 실측), 그 모드가 빈칸 크기로 `localPosition`·크기를 직접 정하고 `LayoutElement.ignoreLayout = true` 로 둔다 — 우리 쪽이 그 뒤에 크기·위치·글자를 덮어쓴다. 버튼을 못 찾으면(모드 없음·이름 바뀜) 아무것도 하지 않는다.
- **목록 한 줄**: 아이콘(게임 아이콘 캐시), 이름(한글 locale), 가격(통화 기호 + 금액, 물물교환이면 "⇄ 재료 N종" 과 마우스를 올리면 재료 목록), 재고, 등급. 줄을 누르면 오른쪽 구매 창에 그 물건이 올라온다. 선택된 줄은 강조된다. 아이템 위 마우스 올림 툴팁은 격자와 같은 것을 띄운다.
- **목록이 따르는 것**: 신뢰 등급 탭(전체/LL1~4), Trader Search 검색어(`TraderSearchController.Matches` 또는 격자 `FilterPanel` 결과), 게임 카테고리 필터 — 즉 **지금 격자에 보이는 것과 같은 집합**.
- **정렬**: 기본(게임 순서) · 가격 · 이름 · 재고 · 등급, 오름/내림. 가격은 **루블 환산**으로 견준다 — 달러·유로는 **핸드북의 통화 값**(달러·유로 아이템의 핸드북 가격)으로, 물물교환은 **재료들의 핸드북 가격 × 개수 합**으로. 핸드북에 없는 재료가 끼면 그 물건은 정렬 방향과 상관없이 **맨 뒤**. 같으면 이름으로. *(내 판단 — 상인 환전가는 상인마다 달라 견주기 기준이 흔들리고, 핸드북 값은 모든 물건에 같은 잣대다.)*
- **격자 보기의 정렬 모양**: 격자는 순서대로 왼쪽 위부터 빈 곳에 채우므로(`AddAnywhere`), 크기가 다른 물건을 가격순으로 놓으면 앞쪽 빈칸에 뒤쪽 작은 물건이 끼어 "완전한 순서"가 아니게 보일 수 있다. 정확한 순서는 목록 보기가 맡고, 격자 정렬은 "대체로 그 순서" 로 받아들인다. *(내 판단)*
- **기억**: 보기 방식·정렬은 BepInEx 설정에 남겨 다음에도 그대로. 상인마다 따로가 아니라 전체 하나.
- **겉모습(C)**: 줄 배경·구분선·글꼴·가격 색을 플리마켓 화면의 행에서 빌린다. 그 자원을 못 찾으면 B 의 기본 모양으로 그린다(안 깨지게). **C 는 이번 작업에 들어간다**(사용자: "B로 시작해서 C 겉모습 입히는 걸로 진행") — 계획은 B 를 먼저 끝내 확인하고 C 를 두 번째 단계로 둔다. 플리마켓 화면을 아직 한 번도 열지 않은 상태에서도 자원을 얻어야 한다(메뉴 UI 에 이미 올라와 있는 플리 화면 부품에서 찾거나, 못 찾으면 B 모양). "닮았다" 는 같은 크기 스크린샷 두 장(플리마켓 목록·상인 목록)을 나란히 놓고 사용자가 본다.

## 6. 같이 살아야 하는 모드 (실측: `TraderDealScreen` 문자열을 가진 플러그인 9개)

Trader Search, Ultimate Trader Assort Editor, UI Fixes(Tyfon), OpenBarters, WishlistExtended, IOF(flir), CaliberUnderName, QuickTraderLoadTimes, trader restock refresh.
- **Assort Editor 편집 모드**에서는 목록 보기를 숨기고 격자로 돌린다(편집기가 격자 클릭을 가로챈다).
- OpenBarters·WishlistExtended·IOF·CaliberUnderName 은 격자 아이템 표시에 덧그린다 — 목록 줄에는 없어도 된다(실패 아님). 격자 보기에서는 그대로 보여야 한다.
- QuickTraderLoadTimes 가 격자를 늦게 채우면 목록도 그 뒤에 만든다.

## 7. 정해진 것 (만드는 사람이 바꾸지 말 것)

- 구매는 **오직** `Assortment.SelectItem` → 원래 구매 창. 목록에 "구매" 버튼을 두지 않는다.
- 목록의 집합은 상인 격자의 `FilterPanel.GetFilteredItems(_items)` — 격자에 보이는 것과 같은 집합. 목록만의 별도 필터를 만들지 않는다.
- 정렬은 상인 쪽 `TradingGridView.ApplyFilter` 의 정렬 자리에서 바꾼다(`PrepareTraderGrid` 반환값을 줄 세우는 것으로는 안 된다 — §4).
- 클라이언트 플러그인 하나(`src/TraderListView`, net472, BepInEx·Harmony), 순수 로직(정렬 비교, 가격 환산, 요약 문자열)은 `src/TraderListView.Tests` 로 시험한다. 저장소의 다른 플러그인(`GogglesWheel`, `GridWindowScroll`)과 같은 꼴.
- 글자는 한글(사용자 화면). 설정 키 이름은 영어.

## 8. 만드는 사람에게 맡기는 것

- 목록 그리기: 줄 재사용(가상 스크롤) 방식, 줄 높이, 열 너비. 수천 줄에서 멈추지 않을 것만 지킨다(§2).
- 아이콘을 얻는 길(아이콘 캐시 API), 툴팁 띄우는 길.
- 플리 행 겉모습 자원을 어디서 찾는지(C).
- 패치 순서 맞추는 법(`HarmonyAfter`·우선순위 등).
- 설치 스크립트(`tools/install-*.ps1` 꼴)와 설치 기록.

## 9. 확인 (끝났다고 말하려면)

1. 게임에서 AIOTrader 를 열어 목록으로 바꾸고, 가격·이름·재고·등급으로 정렬해 순서가 맞는지 본다. 격자로 돌아가도 정렬이 먹는지.
2. 목록에서 줄을 눌러 오른쪽 구매 창에 같은 물건이 뜨고, 실제로 사서 돈과 물건이 맞게 오가는지(통화·물물교환 각 한 번).
3. 검색어·신뢰 등급 탭을 바꾸면 목록이 격자와 같은 것만 보이는지.
4. EDIT ASSORTS 와 검색창이 겹치지 않는지, 편집 모드에 들어가면 격자로 돌아가는지.
5. 화면은 사용자에게 찍어 달라고 하거나 스크린샷으로 본다(로그만으로 "됐다" 하지 않는다).
6. (C) 플리마켓을 열기 전·연 뒤 두 경우 모두 목록이 플리 겉모습(또는 자원을 못 찾으면 B 모양)으로 깨지지 않고 그려지는지. 플리마켓 목록과 나란히 찍은 스크린샷을 사용자가 본다.
