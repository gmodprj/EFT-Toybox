# ProfilePorter — 내보낸 파일 지우기와 세부 보기 (설계)

2026-11-09. 사용자 요청. 앞선 설계는
[2026-11-08-profile-porter-design.md](2026-11-08-profile-porter-design.md) 이고, 이 문서는 그
위에 **창 쪽 기능 둘**을 더한다.

## 1. 왜 하는가

창에는 지금 내보낸 파일을 **만드는 길만** 있다. 목록에 이름과 개수만 뜨고, 그 파일이 무엇을
담고 있는지는 열어 볼 수 없으며, 한 번 만든 것은 지울 수 없다.

사용자의 말로 두 가지다.

- **지우기** — "잘못 만들어진 것, 더 필요없어서 지우고 싶은 것."
- **세부 보기** — "예전에 만든 게 뭐가 들어있는지 봐야지."

세부 보기는 **되짚어 보는 일**이다. 고르거나 바꾸는 일이 아니다.

## 2. 무엇을 만드는가

### 2.1 지우기

가운데 "내보낸 파일" 칸에 **지우기** 단추를 둔다. 고른 파일 하나를 지우고, 누르면 **한 번
묻는다** — 파일 이름, 아이템 수, 만든 시각을 보여 주고 **되돌릴 수 없다는 것**과 **이미 보낸
우편은 그대로 남는다**는 것을 말한다. 지운 뒤 목록을 다시 읽는다.

**못 읽는 파일도 목록에 띄운다**(사용자 결정, 2026-11-09). 지금 `PorterFiles.List()` 는
역직렬화에 실패한 파일을 로그만 남기고 **건너뛴다** — 그러면 가장 지우고 싶은 "잘못 만들어진
것" 이 창에 아예 보이지 않아 지울 수가 없다. 목록에 `readable: false` 로 올리고, 창은
`(못 읽음)` 으로 적는다. 그런 줄은 **지우기만** 되고 세부 보기·보내기는 막힌다.

### 2.2 세부 보기 (자식창)

파일을 고르고 **세부 보기**를 누르면 자식창이 뜬다. **왼쪽은 나무, 오른쪽은 그 자리의 모습**이다.

| 파일 종류 | 오른쪽에 처음 보이는 것 |
| --- | --- |
| `stash` | 스태시 바닥 격자 — 뿌리들이 **좌표 그대로** 깔린다 |
| `loadout` | **인게임 장비 화면과 같은 슬롯 판** (§4.3) |

왼쪽 나무에서 상자(가방·리그·아이템 케이스·주머니)를 고르면 오른쪽이 **그 안**으로 바뀐다.
안쪽은 **스태시와 같은 격자 방식**이고, 상자 안에 또 상자가 있으면 **끝까지** 들어간다.
슬롯에 꽂힌 것(플레이트·소프트아머·총 부착물)은 격자가 아니라 **슬롯 목록**으로 보인다 —
그것들은 좌표가 아니라 슬롯 이름으로 붙어 있기 때문이다.

## 3. 목표 · 하지 않을 것 · 실패

**목표**

1. 예전에 내보낸 파일 하나를 열어 **무엇이 들었는지** 상자 안까지 알아볼 수 있다.
2. 쓸모없어진 파일을 창에서 **지울 수 있다**.
3. 배치가 **내보낸 그대로** 보인다 — 좌표와 회전(§20 에서 고친 것)이 화면에 그대로 나타난다.

**하지 않을 것 (non-goals)**

- 세부 보기 창에서 **고르거나 보내거나 지우지 않는다.** 읽기 전용이다.
- 파일을 **고치지 않는다** — 항목 빼기·이름 바꾸기 같은 편집은 이번 범위가 아니다.
- 인게임 같은 **3D 미리보기를 만들지 않는다.** 그림은 지금 창이 쓰는 아이콘(`IconService`,
  tarkov.dev) 그대로다.
- 보낸 **우편을 지우는 길은 만들지 않는다** — 모드에 그런 길이 없다(앞 설계 §22.3).

**실패 (anti-goals)** — 돌아가더라도 이것들이면 실패다.

- 지우기가 **프로필이나 백업**을 건드린다.
- 지우기가 **묻지 않고** 지운다.
- 세부 보기가 좌표를 무시하고 전부 (0,0) 에 겹쳐 그려, 사람이 깨진 줄 안다(§5.3 이 막는다).
- 1,361개짜리 파일을 열었을 때 창이 몇 초씩 멈춘다.

## 4. 어떻게 — 정해 둔 것

### 4.1 서버에 라우트 둘을 더한다

창은 파일에 직접 손대지 않는다. 지금도 `porter/` 는 **서버 모드 폴더 안**이고 창은 라우트로만
일한다. 같은 길을 쓴다.

| 라우트 | 본문 | 돌려주는 것 |
| --- | --- | --- |
| `/profile-porter/file-delete` | `{ fileName }` | `{ ok, reason?, fileName }` |
| `/profile-porter/file-detail` | `{ fileName, containerId? }` | §4.2 |

- **열쇠 이름은 반드시 `[JsonPropertyName]` 으로 적는다** — 앞 설계 §5-5 의 함정(camelCase 가
  조용히 null 이 되어 엉뚱한 사유로 거절)을 그대로 밟는다.
- 지우기는 `PorterFiles.PathFor` 가 **이미 하는 이름 씻기**를 거친다. `porter/` 밖의 경로는
  그 함수가 null 을 돌려주므로 거기서 막힌다. **`backups/` 와 프로필은 손대지 않는다.**
- 지우기가 성공하면 서버 로그에 한 줄 남긴다(무엇을 지웠는지).

### 4.2 세부 응답의 모양

한 번에 **한 자리**만 돌려준다. 파일 전체를 통째로 창에 올리지 않는다 — 1,361개를 한 번에
그리지 않기 위해서다(§3 의 마지막 실패 조건).

```
{
  ok, reason?,                 // reason 은 **거절할 때만** 쓴다
  fileName, kind,              // "stash" | "loadout"
  notices: [ "…" ],            // 성공했지만 사람에게 할 말 (§7-2)
  tree: [ { id, name, tpl, contained, kind } ... ],   // 그 자리의 자식들 (나무를 한 겹씩 채운다)
  view: {
    kind: "stash" | "container" | "loadout",
    cellsH, cellsV,            // kind == "stash" 일 때의 바닥 격자
    rows:   [ StashRow ],      // kind == "stash" — 바닥에 놓인 것
    grids:  [ { name, cellsH, cellsV, rows: [StashRow] } ],   // 상자 안의 격자들
    slots:  [ { slotId, slotName, id, tpl, name, stack, contained, summary } ],
    loose:  [ { id, tpl, name, stack, contained, why } ]      // 자리를 못 잡은 것 (§7-2)
  }
}
```

**`view` 는 갈라지지 않고 쌓인다.** `grids`·`slots`·`loose` 는 **함께** 올 수 있다 — 방탄
리그처럼 격자와 슬롯을 **동시에** 가진 것이 흔하기 때문이다(§7-1). 비어 있으면 빈 배열이다.

`StashRow` 는 **이미 있는 것과 같은 모양**이다(`ServerClient.StashRow` / 서버의 `StashEntry`:
`id·tpl·name·stack·contained·x·y·w·h·rotated`). 격자 그리는 쪽을 새로 만들지 않기 위해서다.

**어느 `view.kind` 가 되는가** — 뿌리냐 아니냐만 가른다.

| 고른 자리 | kind | 채워지는 것 |
| --- | --- | --- |
| `stash` 파일의 뿌리 | `stash` | `cellsH/V` + `rows` (+ 자리 없는 것은 `loose`) |
| `loadout` 파일의 뿌리 | `loadout` | `slots` — 인게임 장비 판(§4.3) |
| 그 밖의 자리(상자·방탄복·총·주머니) | `container` | **가진 만큼** `grids`·`slots`·`loose` 를 함께 |

**자손은 어디로도 버려지지 않는다.** 자식 하나를 놓을 자리를 정하는 규칙은 이 순서다.

1. `slotId` 가 그 tpl 의 **격자 이름**과 맞으면 → 그 격자의 `rows`.
2. `slotId` 가 그 tpl 의 **슬롯 이름**과 맞으면 → `slots`.
3. 둘 다 아니거나 격자에 들어가야 하는데 **좌표가 없으면** → `loose` (`why` 에 사유).

슬롯에 꽂힌 것은 좌표가 **원래 없다** — 그것을 "자리 없음" 으로 읽으면 방탄복·총이 통째로
`loose` 로 간다. **2번이 3번보다 먼저**인 것이 그 때문이다.

**상자 하나에 격자가 여럿**이다(리그의 작은 주머니들). 격자 이름은 DB 의 `_name`(`main`,
`1`..`12`)이고 파일의 `slotId` 와 **실제로 같은 글자**다 — 인게임에 보이는 `GridView (5)` 는
표시 이름일 뿐이다.

**칸 수는 서버 DB 에서 읽는다**(앞 설계 §9.3 과 같은 규칙). 상자는 그 tpl 의
`Properties.Grids` 가 격자 이름(`Name`)과 칸 수(`CellsH`·`CellsV`)를 준다. 파일에 적힌
`slotId` 가 그 격자 이름과 맞는 것끼리 묶는다.

**스태시 바닥의 칸 수**는 파일에 없다. 보낸 프로필(`fromProfileId`)이 아직 있으면 그 프로필의
스태시 크기를 읽고, **좌표의 바깥 테두리**(가장 큰 `x+w`, `y+h`)와 견주어 **큰 쪽**을 쓴다.
프로필이 없으면 테두리만 쓴다. 둘 중 하나라도 추측이면 `notices` 로 말해 준다.

> 칸 수는 돌고 있는 DB 가 정하고 **그 사이 바뀔 수 있다**(은신처 등급, 스태시 확장 모드).
> 지금 격자보다 큰 좌표를 가진 항목이 있는데 현재 크기를 그대로 쓰면 `StashGridView` 가 그것을
> 격자 밖에 그려 **사람이 못 본다.** 큰 쪽을 쓰는 것이 그래서다.

**아이템 크기**는 `tpl` 의 기본 크기(`Properties.Width`·`Height`)다. `ItemHelper.GetItemSize`
를 쓰면 안 된다 — 앞 설계 §5-4(같은 케이스가 내용물에 따라 38x4 로도 5x3 으로도 나와 화면이
깨졌다). 회전(`rotated`)이면 가로·세로를 바꾼다. 이 판정은 `ProfileReader.SafeSize` 와
`ReadLocation` 에 이미 있다 — **파일에서 읽는 쪽으로 한 번 더 쓰게 만든다.**

### 4.3 `loadout` 의 슬롯 판

사용자가 보낸 인게임 화면과 같은 자리로 놓는다.

```
헤드셋      모자        얼굴
완장        방탄복      안경
인식표
주무기 1                권총집
주무기 2                칼집
가방        리그        주머니
```

- 칸마다 **슬롯 이름(한국어)**, 그 자리에 든 것의 **이름**, 그리고 **`summary`** 를 적는다.
  빈 슬롯은 빈 칸.
- `summary` 는 **서버가 만든 짧은 글**이다(§7-4). 창은 `upd` 스키마를 모른 채로 둔다.
- **안이 있는 것**(가방·리그·주머니·완장)은 칸이 눌린다 — 누르면 오른쪽이 그 안쪽 격자로
  바뀐다(`grids`). 나무에서 고르는 것과 같은 자리다.
- 슬롯 이름 대응은 서버가 안다: `Headwear`·`Earpiece`·`FaceCover`·`Eyewear`·`ArmorVest`·
  `TacticalVest`·`Backpack`·`Pockets`·`ArmBand`·`Dogtag`·`FirstPrimaryWeapon`·
  `SecondPrimaryWeapon`·`Holster`·`Scabbard`. **보안 컨테이너는 내보내지 않으므로 칸도 없다.**
  이 열넷은 내보낸 파일에 **실제로 다 들어 있다**(내보내기는 장비 루트의 자식 가운데 보안
  컨테이너만 뺀다).

**슬롯 이름은 안쪽까지 전부 한국어로 적는다**(사용자 결정, 2026-11-09). 장비 열넷뿐 아니라
`mod_scope`·`mod_magazine`·`patron_in_weapon`·`cartridges`·`Front_plate`·`Soft_armor_front`
같은 안쪽 슬롯도 한국어다. 수십 종이고 모드가 새 슬롯을 더할 수 있으므로 이렇게 한다.

- 사전은 **서버에 둔다** — `slotId` → 한국어 한 장짜리 표. 모르는 `slotId` 는 **영문 그대로**
  내보내고 서버 로그에 한 줄 남긴다(사전에 더할 거리가 로그로 쌓인다). 글자를 지어내지 않는다.
- locale DB 에서 끌어오지 않는다 — 아이템 이름과 달리 **슬롯 이름은 locale 에 없다.**
- 사전과 그 "모르는 것은 그대로" 규칙은 시험으로 가둔다(§4.5 의 5번).

### 4.4 창 쪽

- 새 창 `FileDetailWindow` (`Window`). 본 창에서 `Owner` 를 걸어 자식으로 띄운다. **읽기 전용.**
- 왼쪽 `TreeView` — 한 겹씩 채운다(펼칠 때 그 자리를 서버에 묻는다). 각 줄에 이름과 안의 개수.
- 오른쪽은 `view.kind` 에 따라 바뀐다. 격자는 **지금 쓰는 `StashGridView` 를 다시 쓴다** —
  고르기·끌기를 끄는 `ReadOnly` 를 더한다(새로 베껴 만들지 않는다. 두 벌이 되면 §16.5 처럼
  한쪽만 고쳐진다).
- 아이콘은 본 창과 **같은 `IconService` 인스턴스**를 넘겨 쓴다 — 캐시를 두 번 받지 않는다.
- 창을 닫으면 그걸로 끝이다. 상태를 본 창에 돌려주지 않는다.

### 4.5 시험

순수 판정(= SPT 없이 돌릴 수 있는 것)을 따로 떼어 `ProfilePorter.Tests` 에서 시험한다.
테스트 프로젝트는 **소스를 한 줄씩 링크**하므로(§P2 의 방식) 새 파일도 그렇게 더한다.

시험할 것:

1. 자식 하나를 놓는 **세 갈래 규칙**(§4.2) — 격자 · 슬롯 · `loose`. 특히 **격자와 슬롯을
   동시에 가진 리그**에서 주머니 속 물건과 플레이트가 **둘 다** 나오는지.
2. `slotId` 로 격자 묶기 — 이름이 맞는 것끼리 간다. 맞는 격자가 없는 자손은 **버리지 않고**
   `loose` 로 간다.
3. 좌표 없는 묵은 파일 → 격자에 겹쳐 놓지 않고 `loose` + 알림. 슬롯에 꽂힌 것은 **좌표가 없어도
   `loose` 가 아니다**(판정 순서).
4. 나무 한 겹 — 고른 자리의 **직계 자식만** 나온다.
5. 슬롯 이름 사전 — 아는 것은 한국어, **모르는 것은 영문 그대로**(빈 글자가 되지 않는다).
6. 스태시 칸 수 — 현재 크기와 테두리 중 **큰 쪽**. 밖으로 나가는 항목이 생기지 않는다.

각 시험은 **돌연변이로 검증한다** — 그 판정을 뒤집었을 때 그 시험만 빨개지는지 본다
(§21.4 에서 한 것과 같다).

### 4.6 지우기의 관문

- 지운 **뒤** 목록을 다시 읽어 그 이름이 사라졌는지 창이 확인한다.
- 서버 시험: 없는 이름 → 거절 사유, `porter/` 밖을 가리키는 이름 → 거절(이름 씻기).

## 5. 걸리는 것 · 제약

### 5.1 이 도구는 **파일만** 지운다

지우기는 `porter/<이름>.json` 하나다. 그 파일로 **이미 보낸 우편은 그대로** 남고, 받은 사람의
물건도 그대로다. 확인 대화에 그 말을 적는다 — 안 적으면 "지우면 없던 일이 된다" 로 읽힌다.

### 5.2 백업은 지우지 않는다

`backups/` 는 **들여오기 전 프로필 스냅샷**이라 성격이 다르다. 설치 스크립트도 `-Remove` 에서
그 둘(`porter`·`backups`)을 남긴다. 이번 지우기는 `porter/` 만 본다.

### 5.3 묵은 파일은 좌표가 없다

2026-11-08 에 내보낸 파일 넷은 §20 의 결함 때문에 `location` 이 없다(실측: 1,130개). 이 창에서
그대로 격자에 그리면 **전부 (0,0) 에 겹친다.** 그래서 좌표가 하나도 없는 자리는 `flat`(목록)
으로 보여 주고, 창이 한 줄로 알린다 — "이 파일에는 자리 정보가 없습니다(2026-11-08 이전에
내보낸 파일). 다시 내보내면 자리까지 들어옵니다."

판정은 **"그 자리의 자손 가운데 좌표를 가진 것이 하나도 없다"** 로 한다. 섞여 있으면 격자로
그리고 좌표 없는 것만 뒤에 모아 놓는다.

### 5.4 1,361개

한 자리씩 묻고 그리면 한 화면에 수십 개다. 나무도 펼칠 때 채운다. **파일 전체를 한 번에
창으로 보내지 않는다.** 서버는 파일을 읽어 그 자리만 추려 돌려준다.

### 5.5 이름이 한국어다

파일 이름에 한글이 들어간다(`Nomad-스태시-…`). 라우트 본문은 zlib + UTF-8 이라 지금도 오간다.
새 라우트도 같은 길이다.

## 6. 만드는 사람에게 남기는 것

- 격자 칸 크기·여백·색은 지금 `StashGridView` 가 쓰는 값을 따른다.
- 나무의 줄 모양(아이콘을 넣을지, 개수를 괄호로 적을지)은 만드는 사람이 정한다.
- 슬롯 판의 칸 크기와 글자 배치는 §4.3 의 자리만 지키면 된다.
- 확인 대화는 WPF 기본 `MessageBox` 로도 되고 창을 만들어도 된다 — §5.1 의 세 가지(이름·개수·
  되돌릴 수 없음 + 우편은 남음)가 보이기만 하면 된다.
- 새 라우트 둘을 `ProfilePorterRouter` 의 `BuildRoutes` 에 더하고, `Enabled` 관문을 같이 건다
  (설정에서 모드를 끄면 이것들도 꺼져야 한다).

## 7. 검토에서 나온 것 — 사용자가 정한 둘, 내가 정한 다섯

설계를 쓴 뒤 **다른 사람(검토자)** 에게 "이걸로 계획을 세울 수 있는가" 를 물었다. 거기서 나온
물음을 셋으로 갈라, 사용자에게 물을 것만 물었다.

### 사용자가 정한 것

| 물음 | 정한 것 | 어디에 |
| --- | --- | --- |
| 슬롯 이름을 어디까지 한국어로 | **안쪽까지 전부** | §4.3 |
| 못 읽는 깨진 파일도 지울 수 있게 할까 | **목록에 띄우고 지우기만 되게** | §2.1 |

### 내가 정한 것

**7-1. 격자와 슬롯을 **함께** 가진 용기가 흔하다.** 검토자가 설치본 DB 로 셌다 — 격자를 가진
335종 가운데 **33종이 슬롯도 가진다**(방탄 리그 전부). 처음 쓴 "`grids` 냐 `slots` 냐" 로는
한쪽이 반드시 화면에서 **사라진다.** 그래서 `view` 를 **갈라지는 것에서 쌓이는 것으로** 바꿨다
(§4.2). 자손을 버리지 않는 것이 이 창의 전부다 — 되짚어 보려고 여는 창이기 때문이다.

**7-2. 알림과 "자리를 못 잡은 것" 에 자리를 줬다.** `reason` 은 거절 전용으로 두고, 성공했지만
할 말은 `notices` 로, 격자에 못 놓은 자손은 `view.loose` 로 간다(§4.2). 처음 모양에는 둘 다
담을 데가 없어, 문서가 "창이 알린다" 고 적은 것을 **창이 알 길이 없었다.**

**7-3. 슬롯에 꽂힌 것이 `loose` 로 새지 않게 판정 순서를 못박았다**(§4.2). 플레이트·부착물은
좌표가 **원래** 없다. "좌표 없으면 loose" 를 먼저 적용하면 방탄복과 총이 통째로 샌다.

**7-4. `summary` 는 서버가 만든다**(§4.3). 창이 SPT 의 `upd` 스키마를 알게 되는 것을 막는다 —
지금 창은 전혀 모르고, 그 선을 넘기면 서버와 창 두 곳이 같은 지식을 갖게 된다. 처음 판은
내구도·잔량을 담을 필드조차 없었다. 무엇을 적을지는 **만드는 사람이 정한다**: 묶음 수,
내구도(있으면 `x/y`), 자원·약품 잔량 정도면 된다. 모르는 것은 **적지 않는다.**

**7-5. 스태시 칸 수는 "현재 크기와 테두리 중 큰 쪽"** 이다(§4.2). 칸 수는 DB 가 정하고 그 사이
바뀔 수 있어, 현재 크기만 믿으면 큰 좌표를 가진 항목이 격자 밖에 그려져 **안 보인다.**

### 남겨 둔 낮은 것 둘

- **1,361개를 여는 속도에 관문이 없다.** §3 은 "몇 초씩 멈추면 실패" 라 적었는데 시험은 전부
  순수 판정이다. 라우트가 부를 때마다 파일을 통째로 다시 읽으므로, 나무를 펼칠 때마다 1,361개를
  다시 역직렬화한다. **만드는 사람이 정한다** — 읽은 파일을 잠깐 들고 있거나(이름+쓴 시각으로
  무르게), 그냥 두고 **실측 한 번**(1,361개 파일을 열어 몇 초인지)을 끝났다는 근거로 삼는다.
  이 저장소의 관행은 뒤쪽이다.
- `PorterFiles.PathFor` 가 `private` 이다 — 지우기가 그 이름 씻기를 쓰려면 접근자만 열면 된다.

## 8. 만든 뒤 실측 (2026-11-09)

사용자가 게임을 끄라고 해서 서버를 다시 켜고 쟀다. 설치본은 소스보다 **새것**이다
(모드 DLL 10:13:15 · 창 10:28:22 > 가장 새 소스 10:13:08). 창 설치 스크립트는 게시본이 소스보다
낡으면 **스스로 멈춘다** — 이번에도 한 번 걸려서 `dotnet publish` 를 먼저 했다.

### 8.1 세부 보기

| 재는 것 | 바란 것 | **받은 것** |
| --- | --- | --- |
| 착용장비 파일의 뿌리 | 슬롯 판 14칸 | **`loadout`, slots 14** — 헤드셋·모자·얼굴·완장·방탄복·안경·인식표·주무기 1·2·권총집·칼집·가방·리그·주머니 |
| 슬롯 이름 | 한국어 | **전부 한국어** (안쪽도 — 전면 플레이트·후면 소프트아머·목 보호대…) |
| `summary` | 아는 것만 | `내구 100/100`, `내구 53/55` 등 |
| **리그 안**(§7-1 의 그 경우) | 격자와 슬롯이 **둘 다** | **격자 11개 + 슬롯 12개** — 주머니 속 27개와 플레이트·소프트아머가 함께 나왔다 |

| 부른 것 | 걸린 시간 |
| --- | --- |
| 뿌리(58개, 격자 10x80) | **314ms** |

설계 §3 이 적은 실패선(한 번에 2초)에 닿지 않는다. **파일을 들고 있는 수고(캐시)는 하지
않는다** — §7 이 "만드는 사람이 정한다" 로 열어 둔 둘 중 실측 쪽으로 닫는다. 대신 검토에서

### 8.3 지우기

| 재는 것 | **받은 것** |
| --- | --- |
| 만들고 지우기 | `ok: true` → 목록에서 **사라졌다** |
| 없는 이름 | `"그 파일이 없습니다."` |

| **깨진 파일**(`{` 한 글자) | 목록에 **`readable: false` 로 뜬다** · 세부 보기는 `"그 파일을 열지 못했습니다."` · **지우기는 된다** |

### 8.4 실측이 잡은 결함 하나

응답의 `fileName` 이 **빈 글자**로 나갔다. `PorterFiles.Read` 는 이름을 채우지 않는다(`List`
만 채운다) — 이름은 **파일이 아니라 폴더가 가진 사실**이라서다. 부른 쪽의 이름으로 메우게
고쳤다. 창은 제 이름을 들고 있어 화면은 멀쩡했지만, 계약에 있는 값이 늘 거짓이었다.

### 8.5 아직 사람이 봐야 하는 것

**화면은 못 찍는다**(앞 설계 §17 의 한계와 같다 — 창이 Start 메뉴에 없어 computer-use 가
접근 요청을 받지 못한다). 창을 열어 다음을 눈으로 보아야 한다.

- 장비 판의 자리가 인게임과 같은지(설계 §4.3 의 배치).
- 리그를 눌렀을 때 격자와 플레이트가 함께 보이는지.
- 나무를 펼쳐 상자 안의 상자까지 들어가지는지.
- 격자 칸 크기·아이콘·글자가 깨지지 않는지.
