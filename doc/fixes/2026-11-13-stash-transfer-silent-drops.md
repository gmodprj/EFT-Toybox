# 스태시 교환창에서 가방 안의 것을 끌면 아무 일도 안 일어난다 (2026-11-13)

**증상(사용자 제보).** 스태시 교환창 안에서

1. 내 스태시 → **박스/가방을 열고** → 복수 선택 → 팀원 스태시로 옮김 → **반영 안 됨**
2. 같은 것을 **내 스태시 쪽**으로 옮김 → **반영 안 됨**
3. 내 스태시로 옮긴 뒤 다시 팀원 쪽으로 옮김 → **반영 안 됨**

## 1. 서버 로그가 갈라 주었다 — **요청 자체가 가지 않았다**

| 시각(UTC) | 라우트 |
| --- | --- |
| 03:54:05 | `/stm/members/stash-transfer` → `스태시 전송 완료: 플레이어 → 팀원 … 고른 1개` |
| 03:54:19 · 03:54:46 · 03:56:01 · 03:56:06 · 03:56:48 · 03:58:28 | **`/stm/members/stash-pair` 뿐** |

전송이 성공한 것은 **바닥에 놓인 것 하나를 건넨 03:54:05 한 번**이고, 제보한 시도들에는
`stash-transfer` 가 **하나도 없다**. 게임 로그에도 STM 경고·오류가 0건이다.
서버가 거절한 것이 아니라 **클라이언트가 그 드롭을 전송으로 보지 않았다.**

## 2. 왜 — 정책이고, 코드가 그렇게 적고 있었다

드롭을 가로채는 관문은 `StmTransferHandlesDrop` 이고, 끌어온 것이 그 스태시의 것인지는
`StmTransferSideOwns` 가 본다. 그 함수는 **서버가 준 `side.Items` 목록**과 id 를 맞춰 보는데,
그 목록은 **스태시 바닥에 놓인 것**뿐이다. 함수 머리에 그렇게 적혀 있다:

> 그 스태시의 **바닥에 놓인 것**인가. 가방 안의 것을 따로 건네는 길은 열지 않는다(B1 정책).

창의 안내문도 같은 말을 한다 — *"스태시 바닥에 놓인 것만 건넬 수 있고, 가방을 건네면 안에 든
것은 따라갑니다."*

**그래서 세 경우가 모두 설명된다.**

| 제보 | 무슨 일이 일어났나 |
| --- | --- |
| ① 가방 안의 것 → 반대쪽 | 관문이 거른다 → EFT 의 원래 처리가 돈다 → 두 격자는 **서로 다른 컨트롤러**라 옮겨지지 않는다 |
| ② 가방 안의 것 → 같은 쪽 | 관문이 거른다(같은 쪽은 원래 우리 일이 아니다) → EFT 가 **복제 프로필 안에서** 옮긴다 → 서버로 가지 않으니 다음 새로 고침에 사라진다 |
| ③ ② 뒤에 다시 반대쪽 | ②가 저장되지 않았으니 그 아이템은 여전히 바닥에 없다 → ①과 같다 |

**이 창의 두 격자는 서버가 준 목록으로 세운 복제 프로필이다**(`TryBuildStmTransferGrid`).
거기서 일어난 이동은 어디에도 저장되지 않는다.

## 3. 고친 것 — 조용한 것을 말하게 했다

정책 자체는 그대로 두고, **전송으로 보지 않는 드롭이 우리 창 안에서 일어나면 이유를 적고 막는다**
(`StmTransferBlocksDrop`). 막는 이유는 ②가 더 나쁘기 때문이다 — 원래 코드가 돌면 화면에서는
**옮겨진 것처럼 보이다가** 다음 새로 고침에 사라진다. 조용히 틀린 그림을 보여 주는 쪽이
아무것도 안 움직이는 쪽보다 나쁘다.

| 어떤 드롭 | 이제 상태줄에 뜨는 말 |
| --- | --- |
| 가방·상자 안의 것 | `가방·상자 안의 것은 따로 건널 수 없습니다 — 가방째 건네면 안에 든 것이 함께 갑니다.` |
| 바닥에 있는 것을 같은 쪽에 | `같은 쪽 안에서 옮기는 것은 이 창이 저장하지 않습니다 — 반대쪽으로 끌어야 건네집니다.` |

우리 창 **밖**의 드롭(편집기·플레이어 자신의 스태시 화면)은 한 줄도 바뀌지 않는다 —
관문이 먼저 그것을 가린다.

- `dotnet build client/pitFireTeam.csproj -c Release -p:BuildProjectReferences=false` → **경고 0 · 오류 0**
- **설치하지 못했다** — 제보 시점에 게임이 돌고 있어 DLL 이 잠겼다.

## 4. 정하지 않은 것 — **가방 안의 것을 건널 수 있게 할까**

이번 수정은 "왜 안 되는지 말해 준다" 까지다. **되게 하는 것은 B1 정책을 바꾸는 일**이라
따로 정해야 한다. 열 경우 손댈 자리는 이렇다.

1. **서버** — `stash-pair` 가 바닥 것만 내려준다. 가방 속 자손까지 내려주고,
   `stash-transfer` 가 **부모에서 떼어 내는** 경로를 가져야 한다(지금은 바닥에서 집어 옮긴다).
2. **총량 보존** — 지금 보존 검사는 바닥 목록 기준이다. 자손을 옮기면 **보내는 쪽 가방의 내용이
   줄어드는 것**이 정상이 되므로, 무엇이 줄어도 되는지 다시 정의해야 한다.
3. **저널** — 전송 저널의 항목 모양(무엇을 어디서 떼어 어디에 놓았는지)이 한 겹 깊어진다.
4. **화면** — 지금 격자는 바닥만 그린다. 가방을 열어 들어가는 길
   (ProfilePorter 세부 보기 창이 이미 가진 그 길)을 이 창에도 내야 한다.

**싸게 가는 길도 있다** — 가방을 **통째로** 건넨 뒤 받는 쪽에서 꺼내는 것이다. 지금도 되고,
안내문이 이미 그렇게 말한다. 옮길 것이 가방 하나면 이쪽이 더 빠르다.
