# 2026-11-15 — 프로필 포터 격자의 겹침: **접힌 것을 편 크기로 그렸다**

사용자가 **내보내는 쪽 격자에 항목이 겹쳐 보인다**고 알려 왔다(11-09 에 한 번 고친 자리다).

**원인은 우리 쪽이다. 접힌 아이템을 펴진 크기로 그리고 있었다.**

> **먼저 바로잡는다.** 이 문서의 처음 판(커밋 `26096f47`)은 "자료가 실제로 겹쳐 있다" 고 적었다.
> **틀렸다.** 게임은 겹쳐 놓을 수 없고, 사용자가 그 자리에서 그렇게 지적했다. 접힘을 빼먹고 센
> 내 계산이 겹쳐 보이게 만든 것이다. 아래가 바로잡은 내용이다.

## 정체

`atlas_satchel`(tpl `661c917426ba940d7138e5cf`)의 DB 값은 이렇다.

```
Width 3 · Height 3
Foldable true · SizeReduceRight 1
```

그리고 프로필의 그 아이템은 **접혀 있다.**

```json
{"_id":"6af46038…","_tpl":"661c917426ba940d7138e5cf",
 "location":{"x":6,"y":16,"r":"Vertical"},
 "upd":{"Foldable":{"Folded":true}}}
```

| | 가로×세로 | (6,16) 에서 덮는 칸 |
| --- | --- | --- |
| 우리가 그리던 것 | 3×3 (편 크기, 세움) | 칸 6~8 · **줄 16~18** → 18줄의 벨트 둘과 겹친다 |
| **실제** | 접혀서 2×3 → 세우면 **3×2** | 칸 6~8 · **줄 16~17** → 겹치지 않는다 |

`SizeReduceRight = 1` 이 **가로를 1 줄인다**. 그것을 빼먹으면 접히는 물건마다 한 칸씩 더
차지하는 것처럼 보이고, 그 자리에 놓인 이웃과 **겹쳐 보인다.**

## 재 보니 겹침은 **0** 이다

프로필 11개의 스태시 바닥 전부를 서버 DB 크기로 훑었다.

| 세는 법 | 겹친 짝 |
| --- | --- |
| 접힘을 안 보면(옛 계산) | **46** (Hawk 28 · Buck 7 · Moose 4 · Banshee 3 · Nomad·Wraith 2) |
| **접힘을 보면(바른 계산)** | **0** |

접힌 아이템은 프로필 11개에 **25개**다. 46짝이 전부 그 25개에서 나왔다. **게임의 자료는
처음부터 멀쩡했다.**

## 고친 것

`src/ProfilePorter.Server` 두 자리에 **접힘 보정**을 넣었다.

| 자리 | 무엇 |
| --- | --- |
| `ProfileReader.StashFloor` | 스태시 바닥을 읽을 때 `item.Upd.Foldable.Folded` 를 보고 `FoldedSize` 로 가로를 줄인다 |
| `ProfilePorterService.Row` | 내보낸 **파일**의 세부 보기도 같은 자로 본다(`ProfileReader.FoldedOf` 가 JsonElement 의 `upd` 를 읽는다) |

```csharp
public (int w, int h) FoldedSize(MongoId tpl, (int w, int h) size, bool folded)
{
    if (!folded) return size;
    var reduce = (int)(props?.SizeReduceRight ?? 0);
    return reduce > 0 ? (Math.Max(1, size.w - reduce), size.h) : size;
}
```

`SizeReduceDown` 은 **쓰지 않는다.** 접히는 아이템들이 거기에 **음수**(예: `-1`)를 들고 있어
그대로 빼면 오히려 커진다. 접힘은 오른쪽으로만 줄어든다.

## 설치

서버가 돌고 있어 DLL 이 잠겨 있었다. **이름을 바꿔 치우고 새것을 넣었다**(11-13 과 같은 방법) —
`ProfilePorter.Server.dll.locked-143909` 가 그 옛 파일이고, **서버가 내려간 뒤에 지운다.**
새 DLL 은 빌드 결과와 md5 가 같다. **서버를 다시 띄워야 든다.**

## 값을 치르고 배운 것

- **"자료가 이상하다" 는 결론은 가장 마지막에 온다.** 게임이 허락하지 않는 모양(겹친 스태시)이
  보이면, 그것은 **우리가 덜 본 것**이다. 이번에는 `Foldable` 한 글자였다.
- 크기를 tpl 만으로 재면 **아이템의 상태(`upd`)를 놓친다.** 접힘·부착물처럼 **같은 tpl 이라도
  칸이 달라지는 것**이 있다. `SizeOfAssembled`(부착물)는 이미 그래서 만들었는데, 접힘은 빠져 있었다.
- 46짝이라는 숫자가 **그럴듯해서** 더 위험했다. 숫자가 나왔다고 원인이 밝혀진 것은 아니다.
