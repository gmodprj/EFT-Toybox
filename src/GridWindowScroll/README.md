# GridWindowScroll — 내부 인벤토리 창을 화면 안에 가둔다

가방·상자·트렁크를 열면 내부 격자가 **칸 수 그대로** 창이 된다. 10x10 정도는 괜찮지만 가로나
세로가 15칸을 넘으면 창이 화면을 다 덮거나 아예 화면 밖으로 넘어가 아무것도 고를 수 없다.

이 플러그인은 **한 번에 보일 칸 수를 가로·세로로 못박고, 그보다 큰 격자는 스크롤로 넘겨 보게**
한다. 격자 자체는 손대지 않는다.

## 어떻게 하나

| 하는 것 | 하지 않는 것 |
| --- | --- |
| 격자 묶음(`ContainedGridsView`)을 잘라 내는 뷰포트로 감싼다 | 격자·칸 크기를 줄이지 않는다 |
| 그 뷰포트에 `ScrollRect` 와 마스크를 붙인다 | 아이템 위치·용량·필터를 건드리지 않는다 |
| 창 크기는 뷰포트가 요구하는 크기로 줄어든다 | 서버 쪽 데이터는 전혀 건드리지 않는다 |

칸 좌표와 드래그 판정은 격자의 **지역 좌표**로 계산되므로, 격자를 그대로 두고 부모만 잘라내면
스크롤한 상태에서도 집고 놓는 자리가 어긋나지 않는다. 창고(스태시)가 이미 같은 방식으로
`ScrollRect` 안에 격자를 넣고 있어 게임이 지원하는 길이기도 하다.

한 칸의 픽셀 크기는 게임 자신의 공식(`ItemViewFactory.GetCellPixelSize`)으로 구한다. 값을
박아 두지 않으므로 게임이 칸 크기를 바꿔도 따라간다.

## 구조

| 경로 | 내용 |
| --- | --- |
| `Plugin.cs` | F12 설정 등록 |
| `GridScroll.cs` | `EFT.UI.GridWindow.ShowContents`·`ShowGrids` 에 Harmony Postfix. 한 프레임 뒤에 뷰포트를 만들고 크기를 잡는다 |

창이 내용을 채운 **다음 프레임**에 손을 댄다. 격자 GameObject 는 그 프레임에 막 만들어지고
크기는 레이아웃이 한 번 돌아야 정해지기 때문이다.

창은 재사용되므로 뷰포트는 한 번만 만들고, 열 때마다 크기만 다시 잡는다. 창이 격자 묶음을
새로 붙여 빈 뷰포트가 남으면 치운다(남으면 그 크기만큼 창이 커진다).

## F12 설정

| 항목 | 기본값 | 내용 |
| --- | --- | --- |
| 켜기 | 켜짐 | 끄면 창이 다시 격자 크기 그대로 커진다 |
| 가로 최대 칸 | 12 | 한 번에 보일 가로 칸 수 (3~40) |
| 세로 최대 칸 | 10 | 한 번에 보일 세로 칸 수 (3~40) |
| 휠 한 번에 넘길 칸 | 2 | 마우스 휠 한 칸에 움직일 칸 수 (0.5~10) |
| 스텐실 마스크 사용 | 꺼짐 | 칸이 창 밖으로 비어져 나와 보이면 켠다. `RectMask2D` 대신 `Mask` 를 쓴다 |
| 자세한 기록 | 꺼짐 | 창을 열 때마다 격자 크기와 자른 크기를 로그에 남긴다 |

값을 바꾸면 **창을 닫고 다시 열어야** 반영된다(창을 열 때 크기를 잡는다).

## 빌드와 설치

```
dotnet build -c Release src/GridWindowScroll
pwsh -File tools/install-gridwindowscroll.ps1
```

`E:\Spt\BepInEx\plugins\GridWindowScroll\` 에 DLL 이 들어간다. **게임을 다시 켜야 한다.**

SPT 설치 위치가 다르면 `-p:SptDir=...` / `-SptDir ...` 로 넘긴다.

## 아직 안 한 것

- **드래그로 크기 조절.** 지금은 F12 설정으로만 칸 수를 정한다. 창 모서리를 끌어 그 자리에서
  칸 수를 바꾸고 상자별로 기억하게 하는 것은 다음 단계다.
- **스크롤바.** 마우스 휠과 빈 칸 끌기로 움직인다. 눈에 보이는 스크롤바는 게임 프리팹에서
  가져와야 해서 넣지 않았다.
- 창고(스태시)·장비 화면의 격자는 건드리지 않는다. 창으로 열리는 격자(`GridWindow`)만 대상이다.
